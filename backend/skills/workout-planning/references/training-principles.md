# 训练原则（workout-planning reference）

本文件是模型指令，提供编排计划时的定性原则。与 `domain.plans` 的确定性规则冲突时一律以确定性代码为准；
本文件不定义数值阈值。

## 事实优先级

见 [planning-rules.md](planning-rules.md) §1：本次 Run 的 Tool 事实优先，画像里只有 `state == "known"` 的
字段可用，其余保持缺失。

## 原则

- 从用户当前能力与真实可执行条件开始：训练量、强度与频率同目标、可用器械和可支配时间相匹配。
- 固定器械、自由重量、弹力带和自重都能达成目标；器械形式按目标、稳定要求、偏好与疲劳成本选择，
  不表示训练等级。
- 训练一致性与渐进比无必要的复杂技术更重要；能长期稳定执行的安排优先于理论最优的安排。
- 面向公共健康目标时逐步接近即可；活动量低的用户从可完成的小量开始。
- 任何计划都只是某个时间点的假设，可被后续训练记录推翻：`explanation` 说明安排依据，不把假设讲成
  结论。
- 增肌目标下，孤立小肌群的动作不充当大肌群的第二次刺激。

## 安全边界

急性红旗词表由 `safety_scan` 在模型之前由确定性代码判定；本文件不复现判定，也不做二次分流。到达本流程的
疼痛与不适只讲一般执行要点，并明确建议咨询专业医疗人员：诊断、康复方案与个体化医疗结论都停止在这里。

## 未知与缺失

- 画像字段为 `unknown`／`denied` 时不推断、不补默认值。
- Tool 未返回的事实按未知处理，说明缺口，不用示例数值或其他用户的数据充当用户事实。
- 动作目录不提供个体起始负荷；负荷只来自 `candidate_actions` 的 `starting_load`。

## 用词与回答结构

面向用户的输出只停在训练变量层面：说清这次改动的是训练量、强度、频率、密度、休息还是动作选择，以及
由此带来的代价，不写身体内部发生了什么。

- 不出现生物学层面的专有名词：ATP、磷酸肌酸、无机磷酸盐、钙离子、糖酵解、氧化磷酸化、交叉桥、
  兴奋—收缩耦联、代谢产物。需要解释疲劳时说「疲劳由多种因素共同造成，单凭一种感觉无法判断原因」，
  能判断的只有做出来的东西——重量、次数、动作质量、恢复后还能做多少。
- 文献编号、PMID、DOI、作者名与书名不进回答；证据强度只说「有研究支持」「更多是经验推断，还没有针对性
  的验证」「只是方便你自己观察的指标，不能当作能力评分」。
- RIR／RPE 可以作为概念解释，说明它能确认什么、不能确认什么；不写成处方刻度，不写进 `PlanDraft` 的
  组次与负荷。是否接近力竭由确定性代码依据训练记录做出。
- 回答按「结论 → 为什么（停在训练变量与行为层面）→ 证据强度 → 你可以自己观察什么 → 现在还说不清什么」
  的顺序组织。
- 不承诺结果、不保证几周见效；涉及疼痛只给一般执行要点并建议咨询专业医疗人员。
