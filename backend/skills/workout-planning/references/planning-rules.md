# 计划规则（workout-planning reference）

本文件只写 `SKILL.md` 之外的判断口径。与 `app/domain/plans` 的 `schema.py`／`rules.py` 冲突时一律以源码
为准。

## 1. 事实优先级

```text
本次 Run 的 Tool 事实 → 画像中 state == "known" 的字段值 → 本次请求里的明确说明 → 到此为止
```

没有事实支撑就保持缺失：负荷没有来源就是待校准，趋势数据不足就是数据不足，不补 0、不伪造变化值、不用
示例或其他用户的数据。`facts` 里没有的 `exercise_id` 就是不存在。相对日期（「明天开始」「下周一」）按
`business_day` 折算，折算依据只在事实采集阶段使用。

## 2. 动作选择

- 画像 `training_mode` 为 `bodyweight` 时只安排徒手可执行的动作；为 `equipment` 时视为拥有全部器械，
  可使用目录中的任意器械。`unknown`／`denied` 不推断器械条件；本次请求明确说明的限制仍需遵守。
- 选择顺序（只用于在候选集合内排序）：可执行条件与安全前提 → 目标与动作模式 → 当前可稳定重复的最低必要
  技术难度 → 刺激、疲劳与学习成本的比较 → 保留历史里没有问题且持续有效的熟悉动作。
- 器械形式不表示训练等级：固定器械不自动更安全，自由重量不自动更高级，按目标、稳定性需要、用户偏好与
  疲劳成本选择。
- 检索是子串匹配（标准名＋别名＋器械变体），覆盖打算安排的每一个动作；换动作前用新名字的关键词再检索
  一次，替代动作保持主要动作模式一致。
- 频率数字本身不决定分化模板：在给定次数下如何安排训练日职责，依据动作模式、恢复间隔与用户偏好，不套用
  固定分化名称表。

## 3. 有效工作组与负荷来源

`starting_load` 由代码算得，本 Skill 只需按同一口径解释它：

- 有效工作组＝`set_type='work'` 且满足该记录口径要求的度量：负重动作需 `weight_kg` 与 `reps >= 1` 同现，
  纯自重动作需 `reps >= 1`，计时动作需 `duration_seconds > 0`。
- 同一业务日多次训练时，按（业务日期、训练身份、组序号）取最近一条。
- 数值与来源身份原样使用，不重算、不四舍五入到「好看的数字」。
