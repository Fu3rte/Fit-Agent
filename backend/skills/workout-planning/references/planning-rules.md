# 计划规则（workout-planning reference）

本文件只在 `workout-planning` 命中后随 Skill 正文一起加载。它给出生成计划时**必须遵守**的规则、
可用的训练知识归纳，以及这些归纳的实际来源登记。

权威顺序：`Fit-Agent-LangGraph-重构讨论总结.md` > `LANGGRAPH_REFACTOR_PLAN.md` > 已合入源码。当本节
内容与总结冲突时，以总结为准；本文件不新增总结与已合入源码之外的业务口径。

## 1. 事实优先级与未知处理

```text
用户长期画像中已明确记录的事实（known）
→ 当前可核验的训练记录（有效工作组、训练日期）
→ 计划与历史记录（只作起点，不作当前事实）
→ 不推断、不补默认值
```

- 画像字段为 `unknown` 时是“未知”，不是“没有”，也不是默认值；不得用它凑出目标、频率、器械或
  伤病结论。需要这些事实才能定的部分，标为待确认，而不是替用户决定。
- 数据不足时写明“待校准”或“数据不足”，不补 0、不伪造变化值。
- 业务事实只用本次 MemoryAssembler 装配出的内容，不引入别处记忆、示例数据或其他用户的计划。

## 2. 负荷来源（无历史待校准）

- 起始负荷**只**引用最近一次有效工作组记录（`set_type='work'`；外加重量动作重量与次数完整且次数
  不少于 1，纯自重动作次数不少于 1，计时动作时长大于 0）。
- 没有有效历史时只标记“待校准”，不给出具体重量；用户完成首次试练并记录结果后才产生真实起点。
- 禁止从 PB 反推日常训练重量：PB 是成绩指标，不是当前训练负荷，也不是疲劳指标。
- 加重只能按动作目录的 `min_load_increment_kg`。

## 3. 渐进与回退（Fit-Agent 已冻结口径）

- 同一负荷连续两次完成全部目标组且达到次数上限，下一次按 `min_load_increment_kg` 递增。
- 同一负荷连续两次未达到次数下限，回退到最近一次完整完成的负荷。
- 没有可回退的完整完成负荷时，重新标记“待校准”，不生成具体重量。
- 达到上限加重后，次数回到区间下部；不要求重量、次数和组数同时增加。

## 4. 频率、器械与动作选择

- 频率以画像中用户明确记录的每周可训练次数为准；未记录时先问，不按理想次数设计。
- 器械以画像中明确记录的可用器械为准；器械形式（固定器械、自由重量、自重）本身不表示训练等级，
  按目标、稳定性需要、用户偏好与疲劳成本选择。
- 动作选择顺序：可用器械与安全条件 → 目标与动作模式 → 当前可控难度 → 与已有动作的延续性。该顺序只
  用于筛候选动作；目录可用性与禁用动作排除仍由确定性代码判定。
- 禁用动作按画像中已明确保存的稳定 `exercise_id` 确定性排除；不根据伤病名称推导新的禁用动作。

## 5. 一次修订与用户确认边界

- 计划草稿只有一次修订机会：Evaluator 未通过时由 Planner 修订一次；二次不通过即结束流程并说明原因，
  不产生可激活计划，原 active 计划保持不变。
- 草稿必须由用户确认后才启用；确认前不得声明计划已生效、不得写 active、不得改动原 active 计划。
- 用户拒绝时草稿归档，原 active 计划不变。

## 6. 本 Skill 不做

- 不计算 PB、趋势、月历状态或任何数值：这些由确定性代码给出，模型只解释与使用。
- 不做医学判断、不做安全分流、不评价进步／退步／停滞／疲劳。
- 不定义计划数据结构：统一 Pydantic Schema 与确定性校验器属 Stage 4。
- 不引入 RIR、估算 1RM、训练容量、完成率字段或结论。

## 8. 明确不采用

以下 `Lzheng-fitness` 内容与 Fit-Agent 边界冲突，不进入本 Skill：

- RIR / RPE 等主观用力口径，以及以它们为基础的训练量与疲劳判断；
- P0–L3 训练者分层与专家路由、专家模块选择协议；
- 固定周数周期（如 8/10/12 周）、阶段划分与百分比减量；
- 30/20/10 分钟短时降级版本、按自然日计算的停训或漏练阈值；
- 训练量（组数／次数／容量的具体数值表）、估算 1RM、完成率；
- 医疗、康复或诊断类内容（不做诊断，也不替代专业人员的个体评估）。
