# 计划规则（workout-planning reference）

本文件只写 [SKILL.md](../SKILL.md) 之外的判断口径，不新增数值阈值。与业务侧确定性校验冲突时以工具与模型
校验结果为准。

## 1. 事实优先级

```text
本次 Run 的 Tool 事实 → 画像中已有的字段值 → 本次请求里的明确说明 → 到此为止
```

没有事实支撑就显式写 JSON null，字段本身必须保留：没有重量来源时 `weight_kg` 与 `load_convention` 写
null，没有目标就按「目标未知」处理，不补 0、不伪造变化值、不用示例或其他用户的数据。目录里没有返回的
`exercise_id` 就是不存在。相对日期（「明天开始」「下周一」）用 `calculate_date` 按可信 `business_date`
折算。

## 2. 动作选择

- 训练环境为户外或居家时，默认仅徒手动作可用；其余环境或训练环境未知时，默认动作目录中的全部器械可用。
  这个默认在本次生成或调整中说明。
- 用户明确声明可用器械时，按声明放行对应器械动作；只需补充不可用器械即可收窄范围。不可用器械清单与
  受限动作来自画像字段 `unavailable_equipment` 与 `forbidden_exercise_ids`。
- 选择顺序（只用于在候选集合内排序）：可执行条件与安全前提 → 目标与动作模式 → 当前可稳定重复的最低必要
  技术难度 → 刺激、疲劳与学习成本的比较 → 保留历史里没有问题且持续有效的熟悉动作。
- 器械形式不表示训练等级：固定器械不自动更安全，自由重量不自动更高级，按目标、稳定性需要、用户偏好与
  疲劳成本选择。
- 检索使用 `search_exercises`：`name` 做语义查询（中文、英文、别名与描述文本），`equipment`、`body_part`、
  `target`、`muscle_group` 为目录 canonical 精确筛选；覆盖打算安排的每一个动作。替代动作保持主要动作模式一致。
- 频率数字本身不决定分化模板：在给定次数下如何安排训练日职责，依据动作模式、恢复间隔与用户偏好，不套用
  固定分化名称表。

## 3. 执行条件与负荷来源

负荷只来自本次 Tool 事实，本 Skill 不重算：

- `list_workouts` 里已核实的相关逐组 `weight_kg` 与 `load_convention` 是可用的负荷依据；同动作、同口径的
  已完成记录优先于计划值。
- 当前计划里的 `weight_kg` 与 `load_convention` 是计划值，按原值沿用；计划值与实际完成事实区分，采用实际
  记录时说明依据与不确定性。
- 用户本次明确给出的重量与口径按原值写入。
- 重量有值（包括 0）时必须明确 `load_convention`；目录外动作保留真实名称，`exercise_id` 写 null。
- 数值与来源身份原样使用，不重算、不四舍五入到「好看的数字」。
