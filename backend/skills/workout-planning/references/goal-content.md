# 按目标的计划内容要求（workout-planning reference）

本文件是模型指令：按画像 `goal` 与本次请求表达的训练诉求，决定计划必须包含什么。`goal` 是自由文本；
识别到增肌、增力、减脂一类诉求时按对应小节处理，识别不到时按「目标未知」一节处理。与业务侧校验冲突时
一律以工具与模型校验结果为准；本文件不新增数值阈值。

## 共同要求

- 计划的 `notes` 保留目标原文或用户本次说法，并说明安排的依据。
- `days` 至少一项；休息日 `kind="rest"`，`exercises` 必须是空数组。
- 动作身份只取本次 `search_exercises` 返回的 canonical `exercise_id`；负荷只来自本次 Tool 事实。
- 模式覆盖以本次检索返回的可用候选为准：膝主导、髋主导、水平推、水平拉、垂直推、垂直拉、核心／负重行走
  中，检索不到的模式不硬凑，在 `notes` 说明本次未纳入。
- 目标决定覆盖侧重与训练变量，不决定训练日模板名称。

## 增肌

- 每个主要肌群当周至少有一次直接刺激；孤立小肌群的动作不充当大肌群的第二次刺激。
- 同一肌群的刺激分散到不同训练日。
- 组数与次数区间取中高次数起点，休息按恢复需要安排。

## 增力

- 主线动作排在训练日的前半段，辅助动作服务于主线动作的稳定与容量。
- 主线动作按统一器械规则确定候选：训练环境默认、用户明确声明的可用器械与不可用限制共同决定本次可选动作，
  规则见 [planning-rules.md](planning-rules.md) 第 2 节。膝主导与髋主导各取一个可用候选作为主线，写入
  `weight_kg` 与一致的 `load_convention`。
- 检索结果里没有可用的膝或髋主线动作时，按可用模式安排，并在 `notes` 说明该模式未纳入。不为了凑主线而
  安排本次条件不允许的目录动作。
- 次数区间取偏低起点、组间休息更长；力量目标改变的是覆盖侧重与训练变量，不改变循环模板与输出结构。
- 负荷沿用本次 Tool 事实中的重量与口径；没有时保持待校准，不猜重量。

## 减脂

- 保留力量主线与模式覆盖：减重阶段同样维持动作能力与肌肉量。
- 用训练日内的安排（组间顺序与休息）提高密度，不靠加量堆疲劳。
- 动作目录的模式词表只含抗阻模式，计划不安排目录外的有氧动作；活动量提示按用户已有记录与本次确认给出，
  不写未记录的步数、体重或饮食目标。

## 目标未知

`goal` 缺失或为空时按未知处理，不自行补造目标：

- 用户本次请求里明确说了诉求（增肌、增力、减脂等）：按用户说法安排与说明，并在 `notes` 标注该目标来自
  本次请求、画像目标事实缺失。
- 用户本次请求也没有说：按通用覆盖给出，`notes` 说明画像目标事实缺失、计划按通用覆盖给出。不按任何一节
  的侧重推内容，不替用户选目标，也不从其他画像字段反推目标。
