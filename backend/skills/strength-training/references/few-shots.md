# Few-shot 示例（strength-training reference）

`strength-training` 知识层的三个解释示例，每个按**用户请求 / Tool 事实 / 期望行为**组织，只保留该
场景独有的决策。动作身份用目录已种子的稳定 ID；示例数值不代表任何用户的真实记录。

## 例 1：力量目标解释（General）

**用户请求**：我想把深蹲练得更重，现在计划里 60kg 做 3 组 5 次，为什么重量一直没变？

**Tool 事实**：`read_active_plan` 返回该动作目标处方 3 组、次数区间 5–8、目标负荷 60.0kg，渐进决策
`{"action": "keep", "load_kg": 60.0}`；`read_training_history` 里与当前计划日程关联的训练只有 1 次，
3 组次数为 5、6、6，重量均为 60.0kg。

**期望行为**：

- Tool 决策：关联训练不足两次，规则只能保持 60.0kg，下一步仍是 60.0kg。
- 解释结果：加重需要最近两次关联训练都以同一目标负荷完成全部目标组且每组都不低于上限 8；保持既不是
  退步也不是平台期判断。
- 禁止重算：不给 RPE／RIR、不估算 1RM、不建议测最大重量、不给多周周期或百分比减量，也不替用户改
  次数区间或组数。

## 例 2：满足两次上限后的加重（Planner，adjust_plan）

**用户请求**：按最近的训练调整一下我的计划。

**Tool 事实**：`read_active_plan` 返回目标处方 3 组、次数区间 5–8、目标负荷 60.0kg，渐进决策
`{"action": "increase", "load_kg": 62.5}`；关联的两次训练该动作各 3 组，次数均为 8、8、8，重量均为
60.0kg。

**期望行为**：

- 该动作的 `weighted_reps` 处方把负荷写成 `status` 为 `known`、`weight_kg` 为 62.5，并照抄
  `progression_decisions` 给出的来源训练身份与组序号。
- 组数与次数区间保持 active 原值：只推进重量一个主要变量，次数回到区间下部由实际记录体现。
- 未被证据推翻的训练日、动作与解释原样沿用；`explanation` 写明触发事实（两次均达上限 8 次，按目录
  增重单位 2.5kg 递增到 62.5kg）。

## 例 3：记录不足时待校准（Planner／General）

**用户请求**：深蹲这次没做好，下次直接降到 55kg 吧。

**Tool 事实**：`read_active_plan` 返回目标处方 3 组、次数区间 5–8、目标负荷 60.0kg；两次关联训练为
3 组（5、4、4）与 2 组（5、3），重量均为 60.0kg，更早的关联训练里没有一次完整完成全部目标组。

**期望行为**：

- 两次都判未完成且没有可回退的完整完成负荷，决策为 `needs_calibration`，候选该动作的负荷只写
  `{"status": "needs_calibration"}`；写 55kg 会报 `load_source_mismatch`。
- 按数据不足处理：先补一次可比记录（同动作、同器械与重量口径、正式组、记满目标组数），再按规则决定
  负荷。
- 结构调整作为待确认项单独提出并说明触发事实，不静默替换。
