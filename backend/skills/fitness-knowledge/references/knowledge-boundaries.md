# 知识边界（fitness-knowledge reference）

本文件规定 `fitness-knowledge` 作答时的事实优先级、未知处理、Tool 证据要求，以及可用的一般训练知识清单。

## 1. 事实优先级

```text
用户本次明确说出的诉求与确认
→ 本次只读 Tool 返回的业务事实（画像、当前计划、训练记录、目录）
→ 一般训练知识（§4 的清单）
→ 历史记录与旧计划（只作起点，不作当前事实）
```

- 右侧不得推翻左侧；一般知识与业务事实冲突时，以业务事实为准。
- 一条回答里同时出现一般解释与用户事实时，说清哪部分来自本次返回的记录。

## 2. 未知处理

- 未记录不等于没有，也不等于 0；「用户没填」与「用户明确填为空」是两回事，两者都不得当默认值使用。
- Tool 没有返回的字段一律视为未知；不用常见模板补出一个看起来合理的数值、日期或安排。
- 需要未知事实才能回答的部分：说明缺哪条事实、它由哪个流程或哪条记录补，交给对应流程，不替用户填。
- 动作目录不提供个体起始负荷；具体重量取本次 Tool 事实，本层不推断、不补默认值。
- 目录检索无结果时明确说明缺少该动作，不借用名称相近的其他动作的事实。

## 3. Tool 证据要求

- 问题指向「我」的当前情况（做过什么、目录里有没有、计划怎么安排）时先调用对应只读 Tool；没有返回结果就
  不断言。
- 只依据返回值作答：数值、日期与动作名原样引用，不重算、不改写、不从成绩指标反推日常训练负荷。
- 动作一律对齐 `search_exercises` 返回的 canonical `id` 与 `name`；口语叫法与别名先经检索落到稳定身份，
  再用于后续说明。完整步骤与重量口径从 `get_exercise_details` 读取。
- 画像用 `get_profile` 读取（目标、经验、训练环境、可用时间、伤病与受限动作、不可用器械、禁用动作）。
- 当前计划用 `get_current_plan` 读取（`id` 与完整 `content`）；近期训练用 `list_workouts` 读取。
- 日期口径以可信 `business_date` 为准；今天、后天、本周五、下周一都按该业务日折算，相对日期用
  `calculate_date`。
- 计划、训练记录与目录均为空时明确说明没有数据，不粉饰成「暂未安排」。

## 4. 可用的一般训练知识

以下是本 Skill 可以直接复述的通用原则，全部为定性判断，不含数值阈值：

- 从用户当前能力与真实可执行条件开始：训练量、强度与频率同目标、可用器械和可支配时间相匹配。
- 固定器械、自由重量、弹力带和自重都能达成目标；器械形式按目标、稳定性要求、偏好与疲劳成本选择，不表示
  训练等级。
- 训练一致性与渐进比无必要的复杂技术更重要；能长期稳定执行的安排优先于理论最优的安排。
- 面向公共健康目标时逐步接近即可；活动量低的用户从可完成的小量开始。
- 任何计划都只是某个时间点的假设，可被后续记录推翻：说明安排依据，不把假设讲成结论。
- 进步依赖稳定执行、逐步增加刺激、恢复能力跟上这三类条件；不存在对所有人同样有效的安排。
- 上述原则落到个人身上时，个体化的重量、组数与动作选择由计划流程决定，本 Skill 不代作决定。

## 5. 方法论入口

回答训练概念、方法比较、停滞原因与说法真伪时按以下三个文件组织回答，不另立口径：

- [methodology.md](../../training-theory/references/methodology.md)：六步推理、三层分离、四条反直觉跳跃禁令。
- [myths.md](../../training-theory/references/myths.md)：流行说法的核对表，含每条的证据档位。
- [user-facing-language.md](../../training-theory/references/user-facing-language.md)：用词规约与回答结构。

## 6. 安全边界

锐痛、麻木、放射痛、晕厥、胸部异常不适与异常气短这类信号不属于讨论普通训练强度的范围，只给一般信息并
建议咨询专业医疗人员。出现明确医疗风险时停止相关训练建议并提示就医；本 Skill 不做医疗判断，也不据伤病
名称推导禁用动作。
