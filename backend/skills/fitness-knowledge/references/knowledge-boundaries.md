# 知识边界（fitness-knowledge reference）

本文件规定 `fitness-knowledge` 作答时的事实优先级、未知处理、Tool 证据要求，以及可用的一般训练知识
清单。

## 1. 事实优先级

```text
系统内已固化的确定性口径（红旗词表、计划与记录结构、动作目录可用性、负荷来源与渐进规则）
→ 用户本次明确说出的诉求与确认
→ 本次只读 Tool 返回的业务事实
→ 一般训练知识（§4 的清单）
→ 历史记录与旧计划（只作起点，不作当前事实）
```

- 右侧不得推翻左侧；一般知识与系统内已固化的规则冲突时，以系统规则为准。
- 一条回答里同时出现一般解释与用户事实时，说清哪部分来自本次返回的记录。

## 2. 未知处理

- 未记录不等于没有，也不等于 0；“用户没填”与“用户明确填为空”是两回事，两者都不得当默认值使用。
- Tool 没有返回的字段一律视为未知；不用常见模板补出一个看起来合理的数值、日期或安排。
- 需要未知事实才能回答的部分：说明缺哪条事实、它由哪个流程或哪条记录补，交给对应 Intent，不替
  用户填。
- `starting_load` 状态为待校准的动作不猜测重量：完成首次试练并记录之后才存在真实起点。
- 目录检索无结果时明确说明缺少该动作，不借用名称相近的其他动作的事实。

## 3. Tool 证据要求

- 问题指向“我”的当前情况（做过什么、目录里有没有、计划怎么安排）时先调用对应只读 Tool；没有返回
  结果就不断言。
- 只依据返回值作答：数值、日期与动作名原样引用，不重算、不改写、不从成绩指标反推日常训练负荷。
- 动作一律对齐 `search_exercises` 返回的 canonical `exercise_id` 与 `standard_name_zh`；口语叫法与
  别名先经检索落到稳定身份，再用于后续说明。
- 组事实按 `set_type` 区分：`work` 才是正式组，`warmup` 与 `assisted` 不作成绩。
- 日期口径以 `read_active_plan` 返回的 `business_day` 为准：今天、后天、本周五、下周一都按该业务日
  折算；`coverage` 之外不得推断为休息日，只有落在 `coverage` 内且没有训练日才是休息日。
- 计划、训练记录与目录均为空时明确说明没有数据，不粉饰成“暂未安排”。

## 4. 可用的一般训练知识

以下是本 Skill 可以直接复述的通用原则，全部为定性判断，不含数值阈值：

- 从用户当前能力与真实可执行条件开始：训练量、强度与频率同目标、可用器械和可支配时间相匹配。
- 固定器械、自由重量、弹力带和自重都能达成目标；器械形式按目标、稳定性要求、偏好与疲劳成本选择，
  不表示训练等级。
- 训练一致性与渐进比无必要的复杂技术更重要；能长期稳定执行的安排优先于理论最优的安排。
- 面向公共健康目标时逐步接近即可；活动量低的用户从可完成的小量开始。
- 任何计划都只是某个时间点的假设，可被后续记录推翻：说明安排依据，不把假设讲成结论。
- 锐痛、麻木、放射痛、晕厥、胸部异常不适与异常气短这类信号不属于讨论普通训练强度的范围。
- 上述原则落到个人身上时，个体化的重量、组数与动作选择由计划流程决定，本 Skill 不代作决定。
