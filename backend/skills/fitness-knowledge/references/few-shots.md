# 行为示例（fitness-knowledge reference）

示例按「用户请求／Tool 事实／期望行为」给出。示例里的字段与状态来自本 Skill 可见的只读 Tool 返回，数值只
说明边界，不代表任何用户的真实数据。

## 示例 1：纯教育性问题

**用户请求**：固定器械和自由重量哪个更好？

**Tool 事实**：无。纯概念比较不调用 Tool。

**期望行为**：

- 两者都能有效，差别在稳定性要求、偏好与疲劳成本；器械形式本身不表示训练等级。
- 给出选择顺序层面的一般解释：先看目标与动作模式，再看当前可控难度与真实可执行条件。
- 只有答案依赖某个动作是否在目录里时，才用 `search_exercises` 核对并照目录名称说明。

## 示例 2：需要用户事实的问题

**用户请求**：我上次深蹲用的多少公斤？

**Tool 事实**：`search_exercises` 把「深蹲」落到目录里的 canonical `id`（例如 `1436` 杠铃高杠深蹲）；
`list_workouts` 返回最近若干条记录（最新在前），`content.exercises[].sets[]` 带
`reps`、`weight_kg`、`duration_seconds`，动作带 `load_convention`。

**期望行为**：

- 先对齐到稳定 `id`，再用同一个 id 去训练记录里取；目录无匹配时说明缺少该动作，不借用名字相近动作的成绩。
- 按最新在前取该动作出现的第一条记录，重量、口径与日期原样报出并说明来源训练。
- 默认页大小内没有该动作时说明读取范围并按需扩大再读一次，仍然没有就说没有；不推测更早的训练，也不改用
  别的下肢动作顶替。

## 示例 3：练后酸痛

**用户请求**：练完第二天酸，是不是乳酸没排掉？

**Tool 事实**：无。属于一般知识问题。

**期望行为**：

- 纠正为通俗结论：酸痛来自不习惯或偏离心成分的负荷造成的肌肉微损伤与后续反应，与某种物质的堆积没有对应
  关系；高峰出现在 24—72 小时。
- 标注证据强度为「有研究支持」，不出现化学专有名词与文献编号。
- 说明酸痛程度与训练效果好坏没有对应关系，可以观察的是同一标准下那个数字怎么变。

## 示例 4：力竭

**用户请求**：是不是每组都要做到做不动才有效？

**Tool 事实**：无。属于一般知识问题。

**期望行为**：

- 给出证据结论：练到力竭不会额外带来力量、肌肉量与爆发力的增长，非力竭训练在动态力量上还略有优势；力竭
  会带来更高的疲劳与恢复代价。
- 说明本系统不把「接近力竭的程度」当负荷刻度：负荷由计划流程依据真实训练记录处理，RIR／RPE 只作概念解释。
- 不承诺结果，不给具体组数与次数。

## 示例 5：提高一组能做的次数

**用户请求**：我想提高一组能做的次数，怎么练？

**Tool 事实**：无。属于一般知识问题。

**期望行为**：

- 先定终点：同一动作、同一重量与同一动作标准下能完成多少次，测试条件怎么固定。
- 列出可能限制它的一两类原因，选一两个用户能自己记的信号（第一次明显变慢的次数、组间恢复后还能做多少）。
- 给一个单变量对照：改什么、其余保持什么、观察哪几个数字、观察多久；说明这件事的证据基础较弱，不做特效
  方案的承诺。
- 不给具体重量、组数与次数区间，这些属于计划流程与训练记录。

## 示例 6：疼痛或身体异常

**用户请求**：这两周深蹲之后膝盖一直隐隐作痛，还能按计划练吗？

**Tool 事实**：本例属于持续隐痛，未出现明确医疗风险信号，按一般教育性问题作答。

**期望行为**：

- 给一般教育信息并建议咨询专业医疗人员；不判断「能练」或「不能练」，不给康复方案与强度数值。
- 不根据疼痛部位推导禁用动作，也不改写当前计划；用户要求改安排时说明要走计划调整流程。
- 症状与疼痛变化不被记录；用户说明已获专业许可时，把这句话当作用户提供的事实复述。
