# 行为示例（fitness-knowledge reference）

三个示例按“用户请求／Tool 事实／期望行为”给出。示例里的字段名与状态来自本 Skill 可见的只读 Tool
返回，具体数值只说明边界，不代表任何用户的真实数据。

## 示例 1：纯教育性问题

**用户请求**：固定器械和自由重量哪个更好？

**Tool 事实**：无。纯概念比较不调用 Tool。

**期望行为**：

- 两者都能有效，差别在稳定性要求、偏好与疲劳成本；器械形式本身不表示训练等级。
- 给出选择顺序层面的一般解释：先看目标与动作模式，再看当前可控难度与真实可执行条件。
- 只有答案依赖某个动作是否在目录里时，才用 `search_exercises` 核对并照目录名称说明。

## 示例 2：需要用户事实的问题

**用户请求**：我上次深蹲用的多少公斤？

**Tool 事实**：`search_exercises` 把“深蹲”落到目录里的 canonical `exercise_id`；
`read_training_history` 返回最近若干次会话（最新在前），每组带 `set_type`、`weight_kg`、`reps`。

**期望行为**：

- 先对齐到稳定 `exercise_id`，再用同一个 id 去历史里取记录；目录无匹配时说明缺少该动作，不借用
  名字相近动作的成绩。
- 只把 `set_type` 为 `work` 的组当作正式成绩，按最新在前取该动作出现的第一条会话，日期与重量原样
  报出并说明来源训练。
- 默认条数内没有该动作时说明读取范围并按需扩大再读一次，仍然没有就说没有；不推测更早的训练，也
  不改用别的下肢动作顶替。

## 示例 3：疼痛或身体异常

**用户请求**：这两周深蹲之后膝盖一直隐隐作痛，还能按计划练吗？

**Tool 事实**：本例属于未命中急性红旗词表的持续隐痛，请求到达 `general`。

**期望行为**：

- 给一般教育信息并建议咨询专业医疗人员；不判断“能练”或“不能练”，不给康复方案与强度数值。
- 不根据疼痛部位推导禁用动作，也不改写 active 计划；用户要求改安排时说明要走计划调整流程。
- 症状与疼痛变化不被记录；用户说明已获专业许可时，把这句话当作用户提供的事实复述。
