# 3. 动作目录

> 本章仅搬运已拍设计，不授权实现；验收标准均为待实现验证。

## 本章已拍结论

- 动作目录承载标准动作、别名、器械变式、动作模式、可推荐标记与本地媒体关联；首版只提供完成训练计划所需的一组核心动作，不建设全量动作数据集，不建设独立内容管理后台。
- 动作按 `record_type` 区分三类记录口径：负重次数、自重次数、计时（PLAN.md 2026-09-08 收窄前「业务表设计」L209（历史来源）；现承载见第 3 章）；当前不建设器械辅助／配重抵消的“辅助负重型”，朋友人工辅助是单组执行信息，不是动作记录类型（PRD §5.6）。
- 停用不删除：停用后目录仍保留该动作的别名、负重口径及可推荐标记等语义（PLAN.md 2026-09-08 收窄前「业务表设计」L209（历史来源）；现承载见第 3 章）。
- 只有经过检查并标记为可用于计划的动作，才会被 Agent 主动推荐。

## 责任边界

负责：

- 标准动作、别名、器械变式、动作模式、可推荐标记、本地媒体关联
- `exercises` 表存储职责：标准动作及器械变式、`record_type` 区分、停用不删除（PLAN.md 2026-09-08 收窄前「业务表设计」L209（历史来源）；现承载见第 3 章）
- `record_type` 记录口径的区分与负重口径语义的保留

不负责：

- 全量动作数据集、多语言支持（PRD §6 首版边界）
- 独立内容管理后台
- 打卡草稿中的动作匹配确认交互（第 1、5 章）
- 各 `record_type` 的逐组保存要求与 PR、组级判定规则（第 5、6 章）

## 业务规则

### 3.1 动作身份

- 相似动作名称统一匹配（归一）到标准动作身份；匹配展示与歧义询问的打卡交互规则归第 5 章（PRD §5.6 L163–164）。
- 动作别名、器械变式和负重方式必须能够区分；目录保留负重口径语义（PRD §5.11；PLAN.md 2026-09-08 收窄前「业务表设计」L209（历史来源）；现承载见第 3 章）。不同负重口径不得混比，属比较规则（PLAN.md 2026-09-08 收窄前「业务表设计」`training_sets` 职责行 L217（历史来源）；现承载见第 5 章；PRD §5.8；规则见第 6 章）。

### 3.2 可推荐与本地媒体

- 只有经过检查并标记为可用于计划的动作，才会被 Agent 主动推荐（PRD §5.11）。
- 用户可以选择本地动作媒体目录，用于展示动作图片或 GIF；Fit-Agent 不内置或再分发 `exercises-dataset` 的图片和 GIF（PRD §5.11）。

### 3.1 补充：主要肌群字段（2026-09-12 已拍）

- 目录新增 `muscle`（可空）：动作的**主要肌群**，取值来自既有 exercises-dataset 上游 `target`
  逐行原样写入（24 项首批按精确 id 核对，无缺失、无歧义、无猜测）；未收录保持空值。
- 上游 `muscle_group`（primary synergist）与 `secondary_muscles` 只作来源留痕，不混入 `muscle`。
- 该字段供第 4 章 §4.7 同等刺激替换的「主要肌群交集」判定；缺失值一律 fail-closed，不得猜测。
- 上游已知保守后果（已接受、非缺陷）：上游把深蹲族标记为 `glutes`、保加利亚分腿蹲与腿屈伸为
  `quads`，故二者按 §4.7 判为不等价；不做医学修正、不扩词表、不放宽规则。

## 跨模块约束

- 打卡草稿中的动作匹配、歧义询问与确认：第 5 章（草稿机制见第 1 章）。
- 动作目录种子属系统写入，不走草稿、不得借系统写入绕过用户业务确认：边界见第 1 章「本章已拍结论」草稿适用范围行（PLAN.md 2026-09-08 收窄前「业务表设计」L195（历史来源））。
- `record_type` 决定第 5 章的逐组保存要求（外加负重次数型、自重次数型、计时型：PRD §5.6 L188–190）与第 6 章的组级判定、PR 规则（自重、计时、反向辅助负重不套用“重量越大越好”的 PR：PRD §5.8 L251）。
- 动作与渐进方式的匹配（双重渐进只适用于具有稳定负重和次数区间的动作）：第 4 章（PRD §5.4）。

3. 动作停用不删除：停用后目录仍保留该动作的别名、负重口径及可推荐标记等语义（PLAN.md 2026-09-08 收窄前「业务表设计」L209（历史来源）；现承载见第 3 章）。
