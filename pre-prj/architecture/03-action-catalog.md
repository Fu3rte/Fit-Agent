# 3. 动作目录

> 本章仅搬运已拍设计，不授权实现；验收标准均为待实现验证。

## 本章已拍结论

- 动作目录承载标准动作、别名、器械变式、动作模式、可推荐标记与本地媒体关联；首版只提供完成训练计划所需的一组核心动作，不建设全量动作数据集，不建设独立内容管理后台。
- 动作按 `record_type` 区分三类记录口径：负重次数、自重次数、计时（PLAN.md「业务表设计」L209）；当前不建设器械辅助／配重抵消的“辅助负重型”，朋友人工辅助是单组执行信息，不是动作记录类型（PRD §5.6）。
- 停用不删除：停用后目录仍保留该动作的别名、负重口径及可推荐标记等语义（PLAN.md「业务表设计」L209）。
- 只有经过检查并标记为可用于计划的动作，才会被 Agent 主动推荐。

## 责任边界

负责：

- 标准动作、别名、器械变式、动作模式、可推荐标记、本地媒体关联
- `exercises` 表存储职责：标准动作及器械变式、`record_type` 区分、停用不删除（PLAN.md「业务表设计」L209）
- `record_type` 记录口径的区分与负重口径语义的保留

不负责：

- 全量动作数据集、多语言支持（PRD §6 首版边界）
- 独立内容管理后台
- 打卡草稿中的动作匹配确认交互（第 1、5 章）
- 各 `record_type` 的逐组保存要求与 PR、组级判定规则（第 5、6 章）

## 业务规则

### 3.1 动作身份

- 相似动作名称统一匹配（归一）到标准动作身份；匹配展示与歧义询问的打卡交互规则归第 5 章（PRD §5.6 L150–152）。
- 动作别名、器械变式和负重方式必须能够区分；目录保留负重口径语义（PRD §5.11；PLAN.md「业务表设计」L209）。不同负重口径不得混比，属比较规则（PLAN.md「业务表设计」`training_sets` 职责行 L217；PRD §5.8；规则见第 6 章）。

### 3.2 可推荐与本地媒体

- 只有经过检查并标记为可用于计划的动作，才会被 Agent 主动推荐（PRD §5.11）。
- 用户可以选择本地动作媒体目录，用于展示动作图片或 GIF；Fit-Agent 不内置或再分发 `exercises-dataset` 的图片和 GIF（PRD §5.11）。

## 跨模块约束

- 打卡草稿中的动作匹配、歧义询问与确认：第 5 章（草稿机制见第 1 章）。
- 动作目录种子属系统写入，不走草稿、不得借系统写入绕过用户业务确认：边界见第 1 章「本章已拍结论」草稿适用范围行（PLAN.md「业务表设计」L195）。
- `record_type` 决定第 5 章的逐组保存要求（外加负重次数型、自重次数型、计时型：PRD §5.6 L175–177）与第 6 章的组级判定、PR 规则（自重、计时、反向辅助负重不套用“重量越大越好”的 PR：PRD §5.8 L239）。
- 动作与渐进方式的匹配（双重渐进只适用于具有稳定负重和次数区间的动作）：第 4 章（PRD §5.4）。

## ⚠️ 冲突 / 待拍

- 首版核心动作清单的具体范围与种子数据来源未拍：PRD 只约定“完成训练计划所需的一组核心动作”，具体清单、录入与维护方式待拍（PLAN.md「未拍决策」：新增业务语义）。
- 若清单含计时、等长、技术、有氧等非三类口径的动作（PRD §5.4 L110、§5.8 L239），其在 `record_type` 三类口径中的归类同样无已拍依据，待拍。

## 验收标准（待实现验证）

1. 动作身份归一：相似动作名称统一匹配到标准动作，确认后的记录关联正确动作身份；匹配展示与歧义询问的完整验收随第 5 章打卡验收执行（PRD §5.6 L150–152）。
2. 未标记为可用于计划的动作不被 Agent 主动推荐（PRD §5.11）。
3. 动作停用不删除：停用后目录仍保留该动作的别名、负重口径及可推荐标记等语义（PLAN.md「业务表设计」L209）。
