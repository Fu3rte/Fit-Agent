# 4. 计划与训练指导

> 本章仅搬运已拍设计，不授权实现；验收标准均为待实现验证。

## 本章已拍结论

| 决策 | 选项 | 选了 | 为什么 |
|---|---|---|---|
| 训练历史对照 | A 当前计划 / B 具体计划版本 / C 具体计划版本 + 当次安排快照 | C | 同时还原原计划、已接受的临时调整与实际完成情况，后续计划变化不改写历史 |
| 恢复旧计划 | A 重新激活旧版本 / B 基于旧版本生成新版本 | B | 保持版本顺序清晰，恢复前按最新条件重新校验并确认 |
| 回归期归属 | 当次训练保留回归期标记，确认恢复只影响后续训练 | 已确认 | 切回常规计划不能把回归期历史重新混入常规表现对比 |
| 日程锁定依据 | 后台任务写锁定标记 / 日期规则强制判定 | 到期即锁，并保留已确认完成或漏练时提前锁定规则（2026-09-07） | 停机跨过训练日也不能改期或删除以洗掉分母；锁定字段不是唯一依据，不需要后台锁定任务 |
| 新计划启用时旧版未来日程 | A 同次确认中取消旧版剩余日程并确认新版日程 / B 保留旧版未来日程逐次处理 | A（2026-09-07） | 避免遗留两套未来应训练义务；仅取消旧版未来未锁定日程，已锁定日程与历史不动 |
| 计划启用时日程生成边界 | 按复核节点生成 / 滚动生成固定窗口 | 暂以计划复核节点为边界，生成范围为 `[开始日期, 复核日期)`（2026-09-07） | 启用时按确认的训练安排一次生成至复核日前一天，不依赖用户打开应用或已有打卡；不擅自延伸复核日后的日程 |
| 已生效计划与新限制冲突 | A 按最新限制复核整份计划并阻断 / B 只阻断冲突训练日 | A：发现冲突则阻断整份计划的训练指导，旧计划仍可查看但不得作为可执行建议；修订草稿经校验与用户确认后才能继续 | 不采用 B；不静默修改正式计划，不引入部分可用状态或后台巡检；仍允许记录实际已发生的训练，红旗症状始终阻断常规训练处方 |
| 身体状况更新后的长期计划 | 自动调整 / 先询问用户 | 先询问（2026-09-12）：用户说不需要则不生成或修改计划草稿；用户确认需要后，才基于原计划生成剩余周期调整草稿 | 尊重用户选择，不把身体情况更新自动等同于长期计划变更 |
| 非红旗当次状态处置 | 任一身体反馈停训 / 分层保守调整 | B 细化版（2026-09-12）：普通肌肉酸痛与无痛关节异响不自动停训；影响动作质量但未命中红旗时，可提出保留、减载（方案参数见 §4.3）、同等刺激替换或局部跳过的当次安排草稿；用户确认后才生效且不修改长期计划 | 不把普通训练反应医学化，也不让 Agent 自行宣称用户医学上安全；红旗与不确定安全信息仍优先阻断 |

## 业务规则

### 4.1 计划版本与历史

- 计划先作为草稿展示，用户确认后才正式启用；同一时间只存在一个当前计划（PRD §5.3）。
- 正式计划版本的处方内容不可原地修改；修改计划时保留历史版本，不静默覆盖（PRD §5.3；v1「计划与训练记录的历史」L96–105）。
- `plan_versions` 每行一个正式计划版本，`payload_json` 保存完整处方，只追加、不改写，保留来源版本（PLAN.md 2026-09-08 收窄前「业务表设计」L211（历史来源）；现承载见第 4 章）。
- 计划展示包含计划开始日期和复核日期、每周训练安排、训练日动作顺序、工作组/次数区间/目标用力、渐进方式、当前状态和版本（PRD §5.3）。
- 目标用力只作为处方字段：默认 2，保守调整可提高到 3；界面不出现缩写 RIR，用“每组结束还能再做 2 次”这类自然语言表达；用户从不被要求报告它，组级判定也不使用它（PRD §5.3）。
- 系统在计划确认前检查训练频率、单次时长、器械条件、动作限制和重复动作冲突（PRD §5.3）。
- 首版只提供带复核节点的训练计划块，不实现复杂的周期阶段和自动跨周期切换（PRD §5.3；v1 L217）。
- PPL 作为首版模板数据，不写死为唯一可表示的计划结构，也不建设模板插件系统（v1 L223）。

### 4.2 日程生成与锁定

- 日程按已确认计划中的训练安排生成，不将范围内每个日历日都视为应训练日；生成边界暂为开始日期（含）至复核日期（不含），不根据打卡数或请求“今日训练”的次数生成分母（PLAN.md 2026-09-08 收窄前「业务表设计」L200、L232–238（历史来源）；现承载见第 4 章）。
- `scheduled_sessions` 每行一个应训练名额；没有打卡也存在，提供完成率分母，保存关联、日期及锁定信息（PLAN.md 2026-09-08 收窄前「业务表设计」L212（历史来源）；现承载见第 4 章）。
- 到期即锁：日程与完成率分母在训练日到达（或该次已确认完成/漏练）时锁定；锁定按日期规则强制判定，锁定字段不是唯一依据，不需要后台锁定任务；锁定后不能删除或改期以洗掉漏练（PLAN.md 2026-09-08 收窄前「业务表设计」L197（历史来源）；现承载见第 4 章；PRD §5.5）。
- 未来尚未锁定的安排可经草稿确认换日或删减，不改变已锁定部分（PRD §5.5）。
- 日程锁定不等于当次处方锁定：当天仍可在执行相关训练前确认减组等调整，接受时立即落盘，不得事后倒改（PRD §5.5；v1 L199）。
- 新计划启用时，在同一草稿中展示旧版未来未锁定日程的取消及新版日程；一次用户确认、一个原子事务完成计划切换、旧日程取消、新日程写入、草稿提交与业务版本 +1；取消不物理删除历史，旧版已锁定日程及统计归属不变（PLAN.md 2026-09-08 收窄前「业务表设计」L199、L232–238（历史来源）；现承载见第 4 章）。
- 不授权自动续期或自动跨周期切换（PLAN.md 2026-09-08 收窄前「业务表设计」L238（历史来源）；现承载见第 4 章）。

### 4.3 当次安排与状态调整

- 计划、当次安排、实际记录三者分离：计划表示长期准备怎么练，当次安排表示某次训练准备怎么练，实际记录表示真正练了什么，不能混为一份数据（v1「数据闭环与安排范围」L70–87）。
- “当次安排”不限于今天：用户可以训练结束后反馈，再制定未来几天的安排；每次安排明确对应的训练日期或训练次序（v1 L70–87；PRD §5.5）。
- 当次安排绑定具体计划版本与训练日，保存目标和已接受调整的快照；`arrangement_revisions` 每次接受的完整目标快照及真实接受时间，不只保存差异补丁，日程锁定与处方调整分离（PLAN.md 2026-09-08 收窄前「业务表设计」L213（历史来源）；现承载见第 4 章；PRD §5.5）。
- 已接受的安排快照按原计划条目逐项表达四种处置之一：保留、减载（方案 1–3）、同等刺激替换、局部跳过；快照保存该项的完整最终目标，而不是相对计划的差异补丁（PLAN.md 2026-09-08 收窄前「业务表设计」L213（历史来源）；现承载见第 4 章；PRD §5.5）。只提高目标用力、不改组数与动作时，处置仍记为“保留”，变化只体现在该项保存的最终目标里。
- 同等刺激替换的条目同时保留原动作身份与替代动作身份，并记录该项的最终目标（PRD §5.5、§5.7）。
- 临时调整只影响对应训练，不改长期计划；长期调整及接回方案形成新计划版本（PRD §5.5；v1 L70–87）。
- 长期调整版生效日（2026-09-12 已拍）：草稿生成时按**生成业务日期的次日**固定并展示（20260912 生成 → 20260913 生效），确认时不再改日期、不顺延；确认日等于或晚于该日都允许（版本、安全与有效期校验照旧执行），不追溯改写已锁定或已执行历史，过期日期不补执行；长期调整仍须保留原复核节点、训练频率与未受影响部分，且不是原样续期。
- 迟到确认（2026-09-12 已拍）：不在**确认业务日期**（含当天保留）之前生成日程；因此确认日前的日子不进入完成率分母，`starts_on`／`review_on` 行字段不变、不延长复核节点、不顺延也不补执行；生效范围在创建与确认两点都要求尚未整体过去，整窗已过则明确拒绝。
- 长期调整修订以**当前正式 payload 为基线**（2026-09-12 已拍）：只改受影响条目（保留／减载／同等刺激替换／局部跳过四种处置），未列出的条目、训练日集合、日历循环与复核节点逐字保留；计划 payload 本身必须真的改变，拟议档案补丁不能代替计划本身的业务变化。
- 当次安排的过期按其**绑定的训练日**判定：训练日已过则草稿不可再接受，须重新生成；训练日当天仍可接受，同日可用性沿用既有时序／锁定／状态规则（不套用长期调整的「生成日 +1」口径）。
- 反馈不自动成为正式记录，后续建议不自动成为已接受安排（v1 L70–87）。
- 状态调整表（PRD §5.5；2026-09-12 补充）：正常、普通延迟性肌肉酸痛或无痛关节异响，且无疼痛、肿胀、卡锁、失稳、功能受限等异常表现 → 不自动停训，可保持原安排；一般状态差或非红旗不适已影响动作质量 → 只提出保守的当次安排草稿，可在未受影响部分保持原安排，并对受影响部分减载、作同等刺激替换或局部跳过；一般状态差时也可改为把目标用力保守提高到 3（与减载方案 1 二选一）；明显状态差 → 提供最低训练版（§4.6 最低版）或建议休息，并继续澄清；安全信息无法确认 → 不判断“可以继续”，建议休息并继续澄清；红旗症状 → 不生成常规训练处方，建议线下专业评估。

减载（非红旗状态下的当日／当次保守调整，须用户确认后生效；PRD §5.5）：

| 方案 | 做法 | 参数 |
|---|---|---|
| 1 减容量保强度 | 减少组数和／或减少每组次数 | 默认减少 1 组；原计划该动作 ≥5 组时减少 2 组；重量与目标用力不变 |
| 2 减强度保容量 | 降载到已验证重量的 60%，展示 50–70% 允许区间，由用户选择器械实际可用重量 | 组数、次数与目标用力不变；仅适用于已有已验证重量的动作，未校准动作回退到方案 1 |
| 3 容量强度双减 | 方案 1 与方案 2 叠加 | 沿用方案 1、2 的参数 |
| 4 减频次／停训 | 单次漏练按当次安排内局部跳过；多日停训或周期内降频经确认草稿取消该周期未来尚未锁定的安排；跨复核周期的持续降频按 §4.1／§4.5 形成新的长期计划版本 | — |

- 减载必须经用户确认，只影响对应训练，不修改长期计划，也不宣称用户已获医学许可可以训练；红旗阻断仍优先，不能靠减载绕过（PRD §5.5）。
- Agent 不作医学诊断，也不以模型主观判断替用户确定“能够安全继续”；非红旗保守调整必须说明原因和只影响本次的边界，由用户确认或拒绝。用户拒绝则不落正式安排、不修改长期计划。
- 当次保守调整只改变对应训练的完整目标快照；未受影响部分保持原计划，长期计划版本、复核节点与后续日程不因该草稿自动改变。
- 接受即落盘：用户点击确认接受安排或调整时立即持久化安排及真实接受时间，与草稿提交、领域复核及版本 +1 同事务完成，重复确认幂等；不得先在会话中视为已接受，等打卡或补录时再补写；训练发生时间与系统接受、记录、更正确认时间分别保留，不得倒填（PRD §5.5；v1「调整接受时间与记录规范」L88–95；事务规则见第 1 章 1.4）。
- 后续计划修改不改变历史安排快照；已保存训练记录的对照安排不得被静默覆盖，也不能通过事后减组改写原来的执行标准（v1 L88–95）。
- 未来安排使用时仍须按最新限制和红旗状态复核；提前确认不代表可以绕过最新限制或红旗阻断（PRD §5.5；v1 L70–87）。
- 中断后首次训练，接回方案（§4.6）优先于当日状态调整；状态正常也按接回档执行，不能直接跳回中断前处方（PRD §5.5）。

### 4.4 校准与渐进

- 有可信历史记录时，计划可以参考用户过去的训练负荷；没有可信记录时，系统不得猜测重量，而是将动作标记为需要校准，并提供逐级试重、通过标准和停止条件（PRD §5.4）。
- 每个动作采用与自身类型匹配的渐进方式；双重渐进只适用于具有稳定负重和次数区间的动作；计时、等长、技术、自重、有氧和反向负重动作不强制使用双重渐进（PRD §5.4）。
- 次数区间上限：外加负重动作最多 12 次，自重动作最多 15 次；计时型按每组时长处方，不设次数上限（PRD §5.4）。
- 符合加重条件时，只建议采用器械允许的最小增量（PRD §5.4）。
- 校准、接回、动作替代属于本模块业务流程，不单独拆成大模块（v1 L222）。

### 4.5 使用时安全复核

- 使用当前计划提供训练指导时，按最新限制复核整份计划，而不只检查当天的动作（v1「当前计划的使用时安全复核」L243–252）。
- 发现任一冲突后，整份计划暂不作为可执行训练建议；仍可查看旧计划，并明确提示冲突与阻断原因（v1 L243–252；L55）。
- 身体状况更新后，先询问用户是否调整长期计划；用户说不需要时不生成计划草稿、不修改正式计划，既有安全阻断仍保持；用户确认需要后才通过对话生成修订草稿。
- 长期修订以原计划为基线，保留原宏观周期／复核节点、训练频率与未受影响部分，只对受影响部分微调、减载、作同等刺激替换或删除；经候选计划安全复核、领域校验与用户确认形成正式计划版本后，才可恢复基于该计划的训练指导，不自动提交或覆盖原版本。修订后 payload 必须本身产生真实变化（拟议档案补丁不能代替计划本身的业务变化）。
- 首版采用使用时复核，不建设后台巡检，也不引入计划部分可用的状态（v1 L243–252）。
- 阻断不妨碍历史查看或记录用户实际已发生的训练；事实记录不等于推荐执行其中的动作（v1 L243–252）。
- 红旗症状独立阻断常规训练处方，不能因计划修订成功而自动解除（v1 L243–252；见第 2 章）。
- C 层消息兜底（2026-09-12 已拍，正本见 `08-agent-runtime.md` §8.6）：当前 Run 最新用户消息命中已拍兜底红旗词时，计划草稿（首次建档／长期修订／受限组合）与当次安排草稿都不生成（无草稿行、无处方）；只读 `GET /api/plan/guidance` 不携带聊天 Run 状态，不在覆盖内。

### 4.6 中断与接回

- 触发方式（MVP 不做后台自动检测和主动提醒推送）：① 用户主动说“重新开始”“中断回归”等，直接进入接回评估；② 用户发起今日训练等训练相关操作时，系统根据已确认训练记录计算训练间隔，距最近一次训练不少于 7 天时仅提示确认是否属于训练中断，用户确认后才进入接回评估，不自动修改计划（PRD §5.12）。
- 没有已确认训练记录时不判定为中断，按 §4.4 进入校准（PRD §5.12）。
- 7 天阈值作为可配置的产品约定，不宣称具有医学依据，Agent 不得自行修改（PRD §5.12）。
- 判定输入复用已有数据，不新造概念：中断时长、中断原因（可选）、当前症状与恢复（复用档案的身体情况；安全症状由读取时分类得出）、可用时间或器械是否变化（PRD §5.12）。
- 接回处置结果四种：正常接回、降级接回、最低任务、建议休息或线下专业评估；红旗症状直接进入“建议休息或线下专业评估”，接回判定无权解除红旗阻断（PRD §5.12）。
- 可执行接回方案三档：正常版保留原计划结构，但负荷按本节铁律重新确定；降级版的主项更保守并减少 1 组；最低版只保留启动活动和一个主要动作模式，约 10–20 分钟。前三种处置结果分别生成对应方案，并为未来 3–7 天提供简单日程；“建议休息或线下专业评估”不生成训练处方（PRD §5.12）。
- 铁律：不补课、不进行惩罚性训练；不照搬中断前重量（以最近确认记录为上限按保守比例降载，无记录则按 §4.4 校准）；接回方案作为新计划版本产出，遵守“不静默覆盖”；病后恢复必须由用户明确表示已获专业允许，才可进入普通接回，否则只给最低活动建议或转介（PRD §5.12）。
- 接回期训练标注为“回归期”，不进入常规对比与 PR 统计；回归期标记随训练历史保留，统计口径归第 6 章（v1 L68、L103–104）。
- 接回期不按“1–2 次”自动结束；用户确认恢复常规计划内容所形成的新版本生效后，后续训练才恢复常规口径。恢复不自动化：由用户经复盘确认，基于原计划内容生成并启用经过最新条件校验的新常规版本，不重新激活旧版本（v1 L103–104；PRD §6 L324）。

### 4.7 动作替代

- 当动作不可用、器械缺失或用户拒绝某个动作时，Agent 可以提供同等刺激的候选替代动作：训练目的相同 = `modes` 有交集且主要肌群有交集，并满足器械可用、不存在已确认限制冲突、动作处于启用且可推荐状态；替换结果必须再次由用户确认（PRD §5.7）。等价条件**不含旁记录口径相等**（2026-09-12 已拍）：跨自重／外加负重替换允许；替代动作仍须能映射到已拍三类处方口径（payload 有效性）。
- 替代动作承载不了计划负荷时转未校准（不猜重量）；计划修订里替换直接换成替代动作身份，未受影响条目不因替换而重写（2026-09-12 已拍）。
- 主要肌群取目录 `muscle`（2026-09-12 已拍补充）：取值来自既有 exercises-dataset 上游 `target` 逐行原样写入；上游 `muscle_group`／`secondary_muscles` 是协力肌来源，不混入主要肌群。取值为空或身份读不到时**不得猜测**：该动作按不等价处理、不可作替换候选，也不得把缺失当「无冲突」放行。
- 训练计划不得包含已确认限制覆盖的动作（PRD §5.7；限制语义见第 2 章）。
