## 架构不变量（全局硬约束）

> 本章（第 11 章）按骨架约定并入本文件全局节，不另建章节文件；仅搬运已拍约束，不授权实现。因全局硬约束非业务模块，不套用分章模板，逐条标来源行号；各章已承载的操作细节不在此重复。

### 核心不变量

搬运自 v1「当前架构不变量」（L378–387）七条，逐字保留：

1. Agent 执行句柄可以存在于内存，但任务状态、消息和轨迹必须持久化到 SQLite（v1 L380；持久化底线 L31）。
2. SSE 只负责实时展示；断线或刷新后通过业务接口查询 SQLite 中的 Run、已保存会话内容及草稿当前状态，替换本地展示，不重放事件（v1 L381；PLAN.md L113）。
3. 服务重启后不恢复未完成任务，也不自动重试（v1 L382）。
4. 不引入 Redis、Celery、独立 Agent Worker 或其他外部任务队列（v1 L383；外部队列 L30）。
5. 全局只执行一个 Agent Run，同一时刻只允许一个会话发起对话；首版不支持 Queue 或 Steer（v1 L384）。
6. 新增依赖和模块必须在对应功能讨论时再拍板（v1 L385）。
7. Agent 只能提出业务变更草稿；正式业务事实的变更必须由用户点击确认按钮，经业务接口校验后提交，自然语言同意不直接生效（v1 L386）。

### 架构底盘硬约束

- 运行架构为进程内异步单体，本地单用户场景不引入跨进程协调（v1 L23；PLAN.md L46）。
- 系统拓扑为 Browser → 单个 Python 进程 → 模型 HTTP 端点；本地和云端模型均位于 Agent 进程之外（v1 L25）。
- ASGI 服务为单 Uvicorn Worker，不依赖多 Worker 共享内存或任务协调（v1 L27）。
- 事件循环保护：同步阻塞 SDK 必须通过 `asyncio.to_thread()` 执行，禁止阻塞 Uvicorn 事件循环（v1 L36）。
- 本地模型边界：Ollama 等作为独立 HTTP 服务调用，不占用 Agent 进程内的模型运行逻辑（v1 L39）。
- 业务模块划分为五项业务职责（档案与安全限制、动作目录、计划与训练指导、训练记录与更正、统计与复盘数据）加共用应用层草稿确认流程；业务规则独立于 Agent 框架，应用层负责流程与事务编排（v1 L24；分章正本见第 2–6 章）。
- 部署与访问范围（仅本机、回环监听、无账号系统）具全局约束力，操作规则归第 10 章 10.1（v1 L26）。
