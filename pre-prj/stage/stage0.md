# Stage 0 开发计划：持久化、数据目录与凭据底座

> 状态：阶段范围已授权；消息适配契约已收口，采用框架原生序列化；产品凭据从同库读取；阶段结项以 Windows 自动化与底座人工实测通过为门槛。
> 本轮仅同步授权决策文档，不建表、不写业务代码、不安装依赖、不发起模型调用。
> 本文件细化 `PLAN.md`「粗略阶段路线」的 Stage 0，不改变项目契约及已拍设计。阶段范围与授权直接记录于第 3 节；已拍事项写入对应板块并从待拍列表移除，不另建阶段授权决策表。未拍相关部分仍阻断，其他推荐不视为已确认。

## 1. 阶段目标

为后续业务事务和 Agent 运行时提供可验证的本地持久化底座：

1. 服务能在平台用户数据目录打开唯一 SQLite 数据库，完成编号迁移，以单连接、单锁执行所有读写与事务。
2. 会话、消息、Run 和轨迹可持久保存，运行时存储操作满足已拍原子性、条件更新与幂等约束，但不启动 Agent。
3. 固定业务时区与 Provider 配置可跨重启保存；凭据仅在必要的内部读取路径可见，不泄露到查询投影或诊断输出。
4. 使用临时数据库、假凭据和离线检查留下可复核证据，为 Stage 1–4 提供稳定基础，而不是交付可用的健身产品。

## 3. 本阶段范围

批准以下全部底座任务，无未拍依赖的部分可先实施，不拆成仅连接与目录的小批次，以便交付完整底座。消息适配不再阻断 S0-04 与 S0-06；实际检查中新触发的待拍事项仍须暂停受影响部分；凭据交接与 Windows 阶段门槛见 S0-07 与第 6 节；仍不授权业务、Agent、前端或真实模型调用。

- 最小后端生命周期接线：数据目录定位、打开连接、初始化 PRAGMA、迁移、读取固定配置、关闭连接；不扩展业务路由。
- 唯一共享连接、唯一数据库锁、手写 SQL 和可回滚事务入口。
- 编号迁移与版本检查；运行时四表、固定业务时区及 Provider 配置所需的最小存储结构。
- 运行时存储层操作：创建消息与 Run、按幂等键查询、完成与取消的条件写入、轨迹保存、已保存部分回答的读取。
- 固定业务时区首次初始化和复用；这里只验证时间解释基础，不实现训练日程业务。
- Provider 配置的内部存取、Key 录入/替换/显式删除的存储能力、安全查询投影；不接设置页面或模型请求。
- 底座自动化验证、临时数据库重开检查、Windows 底座人工验收说明和后续交接清单。

## 5. 任务拆分与逐项验收

所有任务按第 3 节已确认范围执行，并遵守剩余待拍事项的阻断边界。任务编号只用于执行跟踪，不是新的决策编号体系。

### S0-01 ✅：开工前只读核对与验证入口

- **工作**：核对已授权范围、已有后端/测试组织、工具链与已选依赖可用性；确定最小测试入口和临时数据隔离方式，优先复用已有设施。
- **依赖**：阶段范围与授权确认。
- **验收标准**：记录 Python 和相关工具版本、已有测试入口、依赖可用/缺失情况；明确每个测试只操作临时目录；新增依赖需求先停下来确认，不直接安装。
- **验证方式**：只读版本/帮助检查、文件检查；记录实际命令及退出码。只在未来获准真实调用时检查凭据环境变量是否存在，本阶段无需读取真实凭据。

### S0-02 ✅：数据目录与数据库生命周期

- **工作**：使用 platformdirs 定位用户数据目录；FastAPI 生命周期内只创建一个 aiosqlite 连接并在退出时关闭；初始化 WAL、外键和 busy_timeout。测试使用隔离目录，不触碰用户库。
- **依赖**：S0-01。
- **验收标准**：Windows 实际路径为 `%LOCALAPPDATA%\Fit-Agent\app.db`，不多出厂商或版本子目录；重启复用原库；连接配置可查询验证；启动失败不继续对外提供可用服务，关闭后不遗留本应用持有的连接。
- **验证方式**：临时目录生命周期测试，查询三个 PRAGMA；关闭后重新打开并读取哨兵记录。Windows 实机记录路径及停服后文件可操作性。若运行 Web 启动检查，同时验证回环绑定与基本 Host/Origin 拒绝行为，不新增业务端点。

### S0-03 ✅：统一锁与事务入口

- **工作**：所有数据库访问，包括读取和单语句写入，统一经同一 asyncio.Lock；多语句事务从 BEGIN 到 COMMIT/ROLLBACK 持锁；禁止事务内模型请求、工具执行及 SSE 推送。
- **依赖**：S0-02。
- **验收标准**：并发读取不能看到本连接未提交的中间状态；事务中途异常不留下部分写入；协程取消不遗留开放事务或被占用的锁；后续读写仍能成功；无绕开锁的生产数据库访问路径。
- **验证方式**：用同步屏障控制两个协程交错，不靠 sleep 猜时序；注入异常与取消并检查回滚、锁释放和后续事务；检查连接访问位置。该锁只保证数据库串行访问，不冒充全局 Agent Run 互斥。

### S0-04 ✅：编号迁移与最小存储结构

- **工作**：实现按序编号迁移及 PRAGMA user_version；建立四张运行时表和时区、Provider 配置所需的最小结构。字段名、索引、文件组织按既定语义确定，不逐项请求拍板。
- **依赖**：S0-03；消息结构遵守 07「消息存储与上下文适配契约」，物理行粒度与索引由实现者确定。
- **验收标准**：空库可初始化，已有旧版本库升级后保留数据；重复启动不重复执行已完成迁移；迁移失败时版本号不虚报成功且不开放后续服务；失败的单次迁移不留下半套结构；遇高于程序支持的库版本停止启动，不降级或重建库。
- **结构验收**：runs.status 仅允许五种已拍状态；client_request_id 全局唯一；error_code、retry_of_run_id 可保存已拍语义；run_events 使用 event_type + payload_json，id 为 INTEGER PRIMARY KEY AUTOINCREMENT；不创建 11 张业务表。
- **验证方式**：空库、带哨兵数据的旧版本库、重复启动、迁移中途失败、未来版本库测试；查询 user_version、表定义和约束，尝试非法状态与重复幂等键。迁移失败恢复策略不得以删除用户数据库替代。

### S0-05 ✅：固定业务时区

- **工作**：首次获取本机时区并持久化，后续只读取已保存值；提供后续业务可消费的时区基础，不加入日程规则。
- **依赖**：S0-04；若可靠的跨平台时区获取需要新增依赖，先按第 7 节处理。
- **验收标准**：首次初始化后重开数据库不更换时区；模拟本机时区改变后，同一绝对时刻计算出的业务日期不变；如来源地区存在夏令时，不能用启动时固定 UTC 偏移替代全年地区规则；检测失败不得静默选 UTC 或其他时区。
- **验证方式**：注入不同本机时区来源并重开数据库，检查原配置及跨午夜业务日期；补充夏令时地区样例。Windows 人工切换时区并重启的步骤注明执行后恢复系统设置；未实际执行则标未验证。到期锁定和完成率分母仍由 Stage 3 验收。

### S0-06 ✅：运行时存储操作与原子性

- **工作**：只实现 7.4–7.5 所需存储操作，不接 Agent、HTTP 或 SSE；保存和读取会话、消息、Run、通用事件，提供条件完成、条件取消和创建幂等能力。
- **依赖**：S0-04。
- **消息契约**：用户请求是随 pending 原子保存的应用事实；框架记录采用 PydanticAI 原生序列化，仅保存本 Run 新增消息并保持顺序与关联，不重复注入用户请求。取消后不补存晚到框架快照，接受收尾记录不完整。下一轮保留用户请求及已确认结果、排除未完成回答并标明中断，不自动续跑旧请求；实际投影与业务状态核对留在 Stage 4，详见 07「消息存储与上下文适配契约」。
- **验收标准**：
  1. 用户消息与 pending Run 同事务创建，中途失败两者均不新增；同一 client_request_id 重复或并发调用只产生一组记录并返回已有 Run。
  2. 仅 running Run 可在同一事务写完整 Assistant 消息并改 completed；任一步骤失败不得只完成一半。
  3. 取消仅能从 pending/running 条件更新为 cancelled，并同事务写取消事件；取消成功后，迟到完成操作不能写入完整 Assistant 消息或覆盖终态。
  4. 通过可控并发测试证明完成/取消不能同时成功；不得因取消失败却留下“取消成功”事件。
  5. 重开数据库仍能读取已保存会话、消息、Run、事件及部分回答；部分回答可区分于完整成功 Assistant 消息；不要求恢复未落盘片段。
  6. 重试指针可保存，但不实现重试调度；run_events.id 只作行身份，无恢复游标或重放接口。
  7. 假消息覆盖原生 JSON 往返、多请求/响应及工具调用/结果顺序、本 Run 增量保存与用户请求关联；完整消息与 completed 同事务批量提交，不把物理行粒度当成事务边界。
  8. 用可控时序先提交取消，再提交假晚到快照和迟到成功结果；验证没有新增框架快照、成功回答或终态覆盖，此前保存的请求、部分回答与事件仍可读取。
- **验证方式**：临时文件库重开测试、约束测试、故障注入与可控并发测试；使用假消息和假事件。存储层测试不声称已验证实际流式断线、模型取消或服务重启恢复。

### S0-07 ✅：Provider 配置与密钥存储边界

- **工作**：在同一数据库持久化 Provider 配置与明文 Key；提供内部录入、替换、显式删除及默认安全查询投影；将必要的内部取 Key 路径与公开查询投影隔离。
- 环境变量交接限制适用于真实验证进程；产品运行时按需从同库 Provider 配置读取 Key，不另建进程或环境变量交接层。理由：保持已拍单进程与同库存储边界。
- **依赖**：S0-04；真实调用接线不在本任务实现。
- **验收标准**：录入、替换、删除结果跨重开保持；默认查询只返回 has_api_key，不返回完整 Key，首版底座不主动增加掩码字段；假 Key 不进入捕获的响应投影、日志、Trace、run_events 或异常详情；仅允许存在于批准的 Provider 存储位置，不复制到消息或其他表。
- **验证方式**：运行时生成辨识度明确的假 Key，验证增改删和重开；触发校验/存储失败并检查实际输出和事件记录，不只做源码字符串扫描；检查未接入的 HTTP/Trace 链路并标注后续待验，不能用本任务替代设置页端到端凭据验收。

### S0-08 ✅：阶段验证与交接

- **工作**：汇总底座测试、运行说明、数据库操作限制、后续接入点及未覆盖验证项；记录版本标识与工作区差异，隔离已有改动。
- **依赖**：S0-02–07。
- **验收标准**：提供可复制的安装前提、测试与最小启动命令；运行证据包括平台、代码版本、实际命令、退出码和结果；说明停服后才手动复制/删除目录，运行中备份仅可经 Backup API，不提供在线下载；没有备份入口时明确其未实现，不声称能禁止操作系统用户自行复制文件。
- **验证方式**：执行本阶段自动化测试、一次停服重开持久性检查及授权范围内的 Windows 底座冒烟；检查文档与实际入口一致；核对未实现内容仍留在后续阶段，最终发布清单仍为待收口状态。
- **交接产出**：运行说明、数据库操作限制、后续接入点与 Windows PowerShell 人工验收方案见 `pre-prj/stage/stage0-handover.md`；本轮 Linux（WSL2）运行证据（平台、代码版本、命令、退出码、结果）见 `pre-prj/stage/evidence/S0-08-linux-wsl2-2026-09-09.md`。Windows 同版本底座自动化测试与人工实测**未执行**，阶段正式结项仍待该证据回传。

## 6. 验证方式与证据要求

### 自动化验证

- 以存储层离线测试为主，复用现有测试设施，不为本阶段引入大型测试框架或浏览器 E2E。
- 每个用例使用独立临时目录和文件数据库；持久化、WAL、迁移与重开测试不能只用内存库替代。
- 覆盖正常流程、非法输入、数据库约束、失败回滚、协程取消、确定性交错及重复请求。
- 不修改开发者实际数据目录，不读取真实 API Key，不访问模型或其他外部网络。

### 人工验证与覆盖边界

- Stage 0 以同版本 Windows 底座自动化测试与人工实测通过为结项门槛，不要求先通过 Linux 验证。理由：直接在目标平台验收，避免将 Linux 检查作为额外前置。
