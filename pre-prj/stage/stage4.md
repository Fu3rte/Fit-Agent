### S4-02：Run 服务、幂等互斥与启动恢复

- **工作**：复用 `RunRepo` 建立应用层 Run 服务；按“先 `client_request_id` 查重、再检查全局活跃 Run”创建；补齐手动重试关联、五态合法流转与启动迁移后的遗留 Run 恢复事务。
- **依赖**：S4-01 契约；第 7、8 章运行时表与事务规则。
- **验收**：相同请求返回原 Run；不同请求遇全局 `pending/running` 返回 `409 conversation_busy`，不创建 Run 或消息；手动重试创建带 `retry_of_run_id` 的新 Run，不复活旧 Run；启动时在一个事务内将全部遗留 `pending/running` 改为 `failed`，同时写 `interrupted_by_restart` 事件，失败注入时全部回滚。
- **验证**：临时数据库覆盖重复请求、跨会话冲突、合法／非法状态流转、关闭重开、多个遗留 Run 和事务失败回滚；检查终态不可恢复。

### S4-03：执行驱动、取消与 draining

- **工作**：实现单进程异步执行驱动，将 Run 从 pending 推进至 running 和唯一终态；取消同时更新持久化状态并尽力中断当前底层调用；底层调用未实际退出时保持 draining，占用全局执行名额。
- **依赖**：S4-02；S4-01 的取消与流式能力结论。
- **验收**：cancel/complete、cancel/fail 竞态只能提交一个终态；取消后不得写迟到 Assistant 成功消息、摘要或草稿通知，也不得启动后续模型／工具调用；无法立即停止的调用退出前，新请求仍返回 busy，退出后才释放名额；SSE 断开或刷新不触发取消；已发生业务副作用不伪装回滚。
- **验证**：可控阻塞桩覆盖 pending 取消、running 取消、终态重复取消、完成竞态、底层延迟退出和 SSE 断开；确认无后台任务或活跃名额泄漏。

### S4-04：消息上下文与业务工具接线

- **工作**：用框架原生消息序列化构造历史；每次 Run 从正式档案、限制、计划及所需统计读取最新业务事实；接入 Stage 3 内部草稿创建服务和只读查询服务。Agent 只可读取业务数据、提出 Pending 草稿或生成回答，不暴露 confirm/discard/void 等正式写入能力。身体状况更新不自动生成长期计划：先询问用户，用户说不需要则不调整；确认需要后才以原计划为基线生成保留宏观周期、复核节点、训练频率与未受影响部分的调整草稿。同日非红旗反馈只进入当次安排，普通肌肉酸痛与无痛且无功能异常的关节异响不自动停训；保守调整可保持、减载、同等刺激替换或局部跳过，用户确认后才生效且不修改长期计划；红旗与安全信息不明仍阻断。
