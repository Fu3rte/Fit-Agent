# Fit-Agent Trace 采集方案

字段、统计及接口边界见 [Trace 数据与报告契约](trace-observability-contract.md)。

## 1. 范围

每次 Agent 执行建立一条 Trace，以 Span 记录根运行、轮次、模型、工具、压缩及确认保存的耗时、结果和白名单属性。真实聊天运行同时导出到 Langfuse Cloud；评测回放与网页裁判使用独立 Trace、环境和费用口径。

采集运行及模型首正文延迟、模型 Token 和缓存用量、工具执行与后处理耗时、压缩及确认保存耗时。本地报告统计最近 30 天的调用数、失败率、取消率、平均耗时、p50、p95、最大耗时及最慢 20 次调用，注明有效样本数。

指标来自真实执行及模型返回值。前端使用既有业务起止时间展示回答用时，不增加 HTTP、SSE 或业务 JSON 字段。

## 2. 记录器与故障隔离

沿用 Pi telemetry 的显式父上下文、callback 包装及运行内存收集模式：

- `start_span(name, attributes, callback)` 等待 callback 完成后结算，callback 恰好执行一次，原样传递业务返回值和异常。
- 创建 Span 失败时使用无记录上下文执行同一 callback；纯观测的属性、结算、初始化、存储及清理故障隔离，不改变业务结果。
- 业务与观测同时失败时保留原始业务异常。协作取消、进程退出和业务校验继续沿用现有控制流。
- 属性只允许白名单字段，已结算 Span 拒绝迟到更新；父操作等待必要子操作及线程收尾后结算。

每条 Trace 使用一个运行级记录器。根身份为 `uuid4().hex`，Span 编号从 1 递增，根父编号为空。业务关联使用既有 `session_id/run_id/operation_id`；编辑和重新生成建立新 Trace，Steering 复用当前运行上下文。

## 3. 生命周期接入

- `agent_run`：HTTP 受理成功时建立唯一记录器，计时起点取真实受理时间，覆盖调度、请求投影、执行及业务终态提交；结局沿用真实业务结果，终态提交失败记 failed。
- `turn`：位于根下，覆盖实际 `turn_start` 至 `turn_end`，等待模型、工具及轮次收尾。
- `model`：覆盖真实请求、响应流消费及底层关闭，普通和恢复请求挂在真实父操作下，摘要调用挂在 compaction 下并区分用途。
- `tool`：覆盖准备、执行及后处理，并行工具共享 turn 父节点；准备拒绝时保留实际失败结果，执行耗时未知。
- `compaction`：覆盖准备、摘要及检查点提交，区分 threshold 和 overflow，校验或提交失败记 failed。
- `confirmation`：已受理确认的执行负责人在受理事务返回后建立独立 Trace，覆盖校验、保存及结果确定；同键和已保存快照复用不新增根。

模型 Span 覆盖取消、异常及提前关闭的收尾。工具 `is_error` 记 failed；模型合法 length 响应记 completed，Agent 输出上限沿用业务失败结局。

Agent 首正文延迟从受理起点算至安全投影后的首个非空正文进入 SSE 队列；模型首正文延迟从请求起点算至首个非空正文增量。浏览器绘制和网络传输由客户端测量。

## 4. 存储与清理

`backend/app/agent/telemetry.py` 负责记录器、Span、SQLite 存储及整批写入，使用现有 `aiosqlite`，数据库为 `backend/data/trace.db`，仅保存 `spans` 表。

执行期间记录在内存；根操作收尾后由 HTTP 主事件循环一次事务尝试写入整条 Trace，随后释放记录器。线程显式接收记录器和父 Span，共享内存登记受保护，落库等待线程及子操作结束。

成功顺序固定为业务终态提交、根结算、尝试写入 Trace、发送终态通知或返回确认响应。根耗时截止业务终态提交，观测写入可能增加通知等待时间；观测失败后仍通知真实业务结果。

启动及每次写入按根开始时间整体清理超过 30 天的链路。事务失败回滚并释放本次事务，同一连接继续承接后续 Trace；初始化失败关闭新连接。

内存收集在强制退出时可能丢失当前 Trace，观测故障也可能缺样；已提交业务记录保持真实状态。报告仅描述已落库终态链路。

## 5. 本地报告

`backend/app/agent/trace_report.py` 只读诊断数据库，从 `backend/` 执行：

- `python -m app.agent.trace_report metrics`：分组指标与最慢调用。
- `python -m app.agent.trace_report show --run-id <UUID>`：一次 Agent 执行。
- `python -m app.agent.trace_report show --operation-id <UUID>`：一次确认保存。

输出 JSON；参数、数据校验或数据库读取失败直接报错。

## 6. 前端运行用时

复用 `started_at/finished_at` 的 UTC 毫秒时间差，除以 1000，保留一位小数；零差值展示 `0.0` 秒。Trace 报告继续使用 `perf_counter`，前端业务时间差可能受系统时钟调整影响。

- running 轮次隐藏用时并保留已知测量；非 running 且起止齐备时展示。
- 同 run_id 合并较早 running/unknown 快照或未知账本时保留已知时间，其余状态、身份和条目沿用传入数据。
- unknown 且起止齐备时展示用时，同时保留结果未知提示和显式重试入口。
- 确认保存独立轮次、未受理占位及测量不完整的轮次不展示 Agent 用时。
- 文本位于该轮回答之后、状态及未知操作提示之前，沿用现有容器、字号和颜色。
- 最终时间通过既有查询及终态历史刷新获取；不补客户端结束时间，不新增轮询、定时器或持久化字段。

## 7. 安全与验证约束

仅记录操作名、可信身份、模型、用量、时间和受控错误码，按操作类型执行 Pydantic 及凭据校验；拒绝记录连同子树剔除，保持链路完整。对话、伤病、附件、工具参数和结果、凭据及原始异常详情不进入 Trace。

验证覆盖真实模型、并行工具、失败、取消、断连、压缩、确认幂等、父子关系、计时边界、未知用量、统计公式、30 天清理及敏感信息边界。

事务锁冲突、初始化失败及同连接恢复通过隔离 SQLite 验证；性能和存储测量写入隔离库，生产观测库只读核查。分别测量整批写入耗时、存储增长和真实运行额外开销，不向生产报告混入构造样本。

## 8. Cloud 导出与客户端观测

- 使用独立 `TracerProvider` 与公开 `Langfuse(tracer_provider=...)` 接入导出；终态快照通过公开 OTel `start_span(start_time=...)` 与 `end(end_time=...)` 写入真实历史起止时间。
- 一次业务运行对应唯一 Trace，`model` 导出为 generation，`tool` 导出为 tool，其余业务 Span 导出为 span；自有 instrumentation scope 精确过滤。
- 本地 SQLite 写入、Cloud 入队与终态通知相互隔离；Cloud 入队非阻塞、有界（容量 1024），关闭等待 5 秒有界排空，网络故障不改变业务结果。
- 浏览器在通过校验的发送入口以 `performance.now()` 计时，在前端解析确认终态、用户停止或断连时结算；客户端时长与首正文通过独立只写接口上报为同一 Trace 的 `client_attempt` 节点，两项测量缺失时直接省略。编辑与重新生成保留业务 Trace 身份规则，Steering 关联当前运行，不建立客户端尝试。
- 待报记录只保留在当前浏览器文档内存，由已有终态查询与历史刷新驱动补报；刷新或关闭页面允许丢失未上报记录，页面隐藏与往返缓存保持活动测量。
- 接收接口按运行归属、终态、去重和 600 秒窗口校验，严格区分接受处理、重复与 Cloud 停用跳过；请求体在解析前逐块限制为 4096 字节。恢复查询与页面卸载不补造时间。
- 费用由 Langfuse Cloud 按项目模型定义计算，只上传真实 provider/model 与四项互斥 Token；无 usage、无匹配价格或部分调用可定价时保留 unknown/partial 口径。本地只记录 `model_calls` 与用量完整性，`priced_calls` 待 Cloud 定价核验后再定，当前省略。
