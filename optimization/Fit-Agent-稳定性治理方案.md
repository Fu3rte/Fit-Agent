# Fit-Agent 稳定性治理方案

前后端交互约定见 [稳定性治理前后端契约](Fit-Agent-稳定性治理前后端契约.md)。

## A 运行架构与技术选择
核心机制为：**入口准入、时间预算、模型级有限重试。**
配套机制为：**取消收尾、有界 SSE 队列、业务结果核对、结构化诊断与故障测试。**

部署约束固定为单个应用进程、单个 Uvicorn worker。
保留现有单线程 Agent 执行器、FastAPI、SQLite 与两种模型协议。
全局同时运行任务数设为 1，不接受后台排队。
已有任务执行期间，超额新任务在受理前返回 503。
同会话运行冲突继续沿用既有 409 契约。

依赖：
- `limits`：内存存储与会话频率限制。

继续使用已有 HTTPX、asyncio、threading.Event 和 RunStream。
依赖版本在实现时锁定，并验证 Python 3.13 兼容性。

运行约束：
- 模型请求恢复保留业务操作证据。
- 取消信号传到实际执行层，并等待实际退出。
- 已提交业务结果保持有效。
- 安全校验在运行时执行，凭据保持隔离。

## B 入口准入与资源上限

### 固定准入顺序

执行 Host/Origin 校验和请求参数校验。
在现有 operation_lock 内检查幂等结果。
相同操作已受理时，按既有契约返回结果。
随后检查会话冲突、频率额度和全局运行名额。
通过后，提交受理记录并登记 RunState。

幂等重放不创建新运行，也不重复扣除运行额度。
全局名额的检查与占用必须在同一主事件循环临界区完成。
频率额度只在新运行受理成功时扣除。
容量拒绝和受理事务失败均不消耗频率额度；受理事务失败时归还预占名额。
受理成功后，名额由 coordinate 独占管理。

### 限流规则

会话额度固定为每分钟 10 个新运行受理。
采用 limits 的移动窗口及内存存储。
频率超额返回 429，并设置 Retry-After。
全局容量超额返回 503，错误码为 capacity_exceeded，并提示稍后重试。
故障封闭期间拒绝新运行，返回 503，错误码为 service_unavailable。
取消与状态查询接口保持可用。
Steering 保留独立的大小与待处理数量限制。

### SSE 队列规则

保留现有完整快照事件结构。
每个运行限制为 256 个待发送事件，当前待发送字节总量不超过 1 MiB。
单个事件不超过 1 MiB，按最终 SSE 的 UTF-8 编码计量，包含 JSON 转义及封装开销。
出队时释放队列额度，另允许一条最大 1 MiB 的在途发送帧。
单事件超限时以 output_too_large 结束运行，保留已有持久化证据。
业务快照必须完整展示后才能确认保存，部分内容不得标记为完整提案。
队列满时触发 slow_consumer，停止接收普通输出并请求取消。
生产线程禁止无限等待队列空间。

终态保存在独立槽位中，不受普通事件队列容量影响。
终态提交成功后才填充该槽位。
发送方按顺序排空可用输出并发送终态。
发送阻塞超过上限时关闭连接，结果通过查询接口读取。
终态排空总时限为 10 秒，从终态槽位填充时起计，包含剩余普通事件和终态的发送。
超过总时限时关闭连接，前端通过查询读取持久化结果。

额度配置集中管理。

## C 时间预算与取消机制

### 固定时间边界

- HTTP 建连：10 秒。
- HTTP 连接池等待：5 秒。
- HTTP 写入：10 秒。
- HTTP 读取下一数据块：60 秒。
- 模型首个有效增量：60 秒。
- 模型有效增量间隔：60 秒。
- 单次模型尝试：180 秒。
- 单次工具执行：30 秒，且受运行剩余预算约束。
- 整个运行：300 秒，包含重试等待与上下文压缩。
- SSE 心跳：15 秒。
- SSE 单次发送等待：10 秒。
- 终态队列排空总时限：10 秒，从终态槽位填充时起计。
- 终态持久化等待：10 秒，从调用 finish 提交终态时起计。
- 取消后的协作收尾等待：10 秒。

使用单调时钟保存运行截止时间。
子调用的预算取自身上限与剩余运行预算的较小值。
HTTP 数据块和 SSE 心跳均不能刷新业务进度截止时间。
模型有效增量包含文本、思考或工具参数的实际增量。

### 取消传播

主事件循环监控截止时间，并设置现有 state.cancel。
工作线程内增加可取消的异步等待监控。
监控触发时，取消模型消费任务并关闭响应流及客户端。
工具调度器停止启动新工具，并通知在途工具退出。
重试退避也接收同一取消信号。
浏览器 SSE 断开时沿用 state.disconnect 请求取消，刷新和关闭页面遵守相同语义。
停止信号到达时立即关闭 Steering 新输入，收尾阶段结算已受理输入。

同步工具需要提供自己的 I/O 超时与协作取消点。
单纯结束 asyncio 等待无法终止已运行的 Python 线程。
收尾等待超过 10 秒时，运行保持占用，应用停止接收新运行。
记录 worker_stuck，由操作者执行人工受控重启。
操作者终止旧后端及其实际启动的工具子进程，确认全部退出后再启动后端。

该路径采用故障封闭策略，避免遗留线程与新任务同时写入。
交付包含适用于实际 Windows 启动方式的停机、退出确认、启动及恢复验收步骤。
严重卡死期间服务保持不可受理，恢复依赖人工介入。

## D 错误分类与重试

### 错误处理契约

- 临时网络故障、明确的短暂 429、502、503、504：进入模型重试判断。
- 额度耗尽、401、403、配置错误：终止，并给出明确错误码。
- 参数错误、版本冲突、权限拒绝：返回既有业务错误。
- 上下文超限：复用现有压缩恢复，每个相关模型步骤只允许一次。
- 用户取消、运行截止、慢客户端：取消收尾，不自动续跑。
- 存储失败或运行时不变量损坏：停止运行并保留诊断证据。

500 仅在协议适配器确认属于临时上游错误时进入重试。
错误分类优先使用 SDK 异常类型与结构化错误码。
所有公开错误沿用凭据过滤与固定安全文案。

### 模型重试

统一放在公共模型消费边界，两个 SDK 保持 max_retries=0。
每次模型步骤最多重试 2 次，即最多尝试 3 次。
整个运行共享 4 次额外恢复请求预算。
每次真实上游请求均消耗已有总请求预算，并独立记录 observation 与真实用量。
正常阈值压缩的首个摘要请求计入总请求预算。
溢出恢复摘要、恢复后的重发及失败重试同时消耗共享恢复预算。

退避采用全抖动：首次随机等待 0 至 2 秒。
第二次随机等待 0 至 4 秒。
有效 Retry-After 作为最小等待时间。
请求等待超过剩余预算或 30 秒时，直接结束本次恢复。

**当前模型步骤仅在首个公开模型事件发布前允许自动网络重试。**
message_start 进入公开队列即关闭该步骤的网络重试窗口。
此后发生断流，即使尚无正文，也结束当前运行并保留已提交业务结果。
后续模型步骤拥有自己的重试窗口。
核实两个适配器 start 的发出时机；请求前生成的内部 start 延迟至请求成功建立后转发。
未发布尝试的 partial 清理后才可重试，已发布消息保持单次生命周期。
保留不完整尝试的诊断记录，不把半截工具参数放进有效上下文。
上下文超限继续遵循已有的一次压缩恢复路径，保持上下文与事件一致性。
依赖故障耗尽重试预算后返回明确的模型服务失败错误。
供应商持续故障期间，新受理的运行仍会在上述预算内尝试访问供应商。

## E 唯一收尾入口与业务副作用

### coordinate 保持终态所有权

复用现有 completed、failed、cancelled、interrupted 状态。
停止原因作为单独字段管理，不新增一套并行终态体系。
新增错误码包括 run_timeout、model_timeout、tool_timeout。
同时包含 slow_consumer 与 output_too_large。
worker_stuck 属于执行尚未退出时的诊断原因，人工重启后通过 interrupted 终态恢复。

超时与用户取消均先记录首个有效停止原因。
模型、工具、运行超时的终态统一为 failed，分别携带 model_timeout、tool_timeout、run_timeout。
用户取消、浏览器断连和慢客户端的终态为 cancelled；慢客户端携带 slow_consumer。
重启恢复的未完成运行进入 interrupted。
取消信号用于停止执行，终态按停止原因裁决；沿用既有凭据安全错误优先级。
已提交终态保持原值，后续信号不覆盖它。

正常收尾顺序固定为：
1. 确认模型、工具和工作线程退出。
2. 核对业务保存结果及运行状态。
3. 通过现有 finish 路径提交终态。
4. 发布持久化终态对应的 SSE 事件。
5. 确认 Steering 入口已关闭，释放全局运行名额。

终态持久化等待超过 10 秒或提交失败时，保留运行占用并关闭 SSE。
等待超时不证明数据库事务已回滚，实际结果通过持久化记录核对。
诊断中记录 terminal_persist_failed，禁止发布成功确认。
应用保持不可受理，由操作者按人工受控重启流程处理。

### 保存与结果未知

复用现有业务快照、版本校验和幂等保存记录。
模型链中的提案准备、提案失效等副作用保持顺序执行与既有幂等约束。
按钮确认通过独立 HTTP 接口核验并保存，使用自己的 operation_id 查询结果。
模型重试仅覆盖模型请求，模型取消不自动撤销独立确认。
模型恢复从当前有效上下文继续，不从用户请求入口重新执行整条链。

取消发生在 COMMIT 前时，遵守现有提交否决契约。
COMMIT 已完成时，保存结果继续有效。
响应丢失后，按原幂等键查询结果。
禁止换一个新键盲目重放写操作。

结果暂时无法核实的操作标记为需要核对。
通过现有保存记录与 operation_id 查询确认后，再决定后续动作。
外部系统接入时，写调用必须携带对方支持的幂等键。

### 重启恢复

确认旧后端及其工具子进程退出后启动应用。
启动时调用已有 recover_interrupted 及业务保存恢复流程。
恢复成功后才开放新运行；数据库仍不可用时保持不可受理。
未完成运行进入 interrupted。
已提交业务数据保留，未提交事务按数据库语义回滚。
重启不自动续跑未完成工具。
前端展示中断原因和可查询的已保存结果。

## F 安全边界与恢复证据

业务安全校验：

- 写入前校验当前用户、会话归属和业务版本。
- 附件工具继续执行会话工作区路径限制。
- 业务保存继续要求快照校验与用户确认。
- 工具参数、输出与日志保持现有凭据检查。
- 模型提示词中的安全要求由运行时校验支撑。

单机本地部署保留现有 Host/Origin 边界。
公开多用户部署需另行完成身份认证、授权和用户级额度设计。
当前方案的限流键不构成用户身份凭证。

诊断使用白名单字段：
run_id、operation_id、session_id、model_step_id、attempt、error_class。
补充 elapsed_ms、stop_reason 和 tool_call_id。
必要时关联已有业务保存记录 ID。
记录队列峰值、重试次数、取消耗时和终态提交结果。

禁止记录 API Key、原始完整提示词及未经筛选的异常正文。
trace 以 run_id 关联，复用现有事件与运行记录。
持久化字段通过现有 SQLite 迁移体系添加。

- `ai/stream.py`：公共模型恢复、逐次调用记账与完整流消费边界。
- `ai/types.py`：传递截止时间及取消上下文。
- `ai/api/openai_completions.py`：HTTPX 分项超时与响应关闭。
- `ai/api/anthropic_messages.py`：相同的超时与错误分类契约。
- `agent/agent_loop.py`：传递共享恢复预算，维护有效上下文。
- `agent/tool.py`：工具截止时间、取消等待与写工具顺序保证。
- `application/session/service.py`：终态与中断恢复契约。
- `application/business/service.py`：保存结果查询与取消并发验证。
- `infrastructure/persistence/sqlite/migrations/`：诊断字段及恢复信息迁移。
- `backend/test/`：接入已有 check 脚手架并增加治理回归入口。
- `pyproject.toml` 与依赖锁文件：新增依赖并锁定版本。
- 前端 SSE 消费处：展示错误原因与已保存结果，正确结束加载状态。

前端保持现有事件协议兼容性。
查询接口保持只读，不触发模型调用或业务写入。

## H 故障验收

- 并发提交相同操作：只创建一次运行，不重复消耗额度。
- 并发提交不同操作：全局仅 1 个运行，无隐藏排队。
- 会话额度超限：429 与 Retry-After 正确。
- 模型建连或读取卡住：在相应截止时间触发停止。
- 模型持续发心跳：业务进度超时仍然生效。
- 首个公开模型事件前短暂失败：重试次数、总请求预算及共享恢复预算符合约定。
- message_start 发布后断流：结束运行，半截工具调用不进入执行。
- 失败重试：上下文无残留 partial，前端无重复 message_start。
- 连续依赖故障：每次运行均在时间及尝试预算内明确失败。
- 退避期间取消：不再发起上游调用。
- 慢客户端：队列、在途帧及字节上限有效，终态可查询。
- 大事件：最大提案及长回复样本验证 1 MiB 上限，超限返回 output_too_large。
- 部分业务快照：不得启用确认保存。
- 浏览器断连：请求取消，响应头丢失时可按原 operation_id 查询。
- 受理事务失败或容量拒绝：频率额度不扣除。
- 终态发送：单次发送与从终态槽位填充起计的 10 秒排空总时限有效。
- 终态映射：模型、工具、运行超时为 failed；用户取消、断连、慢客户端为 cancelled。
- 503 响应：容量超额为 capacity_exceeded，故障封闭为 service_unavailable。
- 取消与 COMMIT 交错：已提交保存可查询，未提交写入不泄漏。
- 工具不响应取消：名额不释放，服务拒绝新运行。
- 终态持久化超过 10 秒或提交失败：不发布成功确认，运行占用保留并进入故障封闭；核对数据库实际提交结果。
- 人工受控重启：验证旧后端及工具子进程已退出，恢复前拒绝新运行。
- 重启恢复：运行标为 interrupted，保存结果可核对，数据库不可用时保持不可受理。
- 凭据出现在上游错误中：前端、日志和数据库均不泄露。

采用本地可控 HTTP 服务触发真实延迟、断流和错误响应。
使用真实 SQLite 验证事务与重启行为。
用可阻塞测试工具验证取消边界，不接入真实生产副作用。
CI 使用缩短的可注入预算验证边界，默认配置另做冒烟测试。
