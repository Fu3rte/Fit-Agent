# 画像身高体重改动契约

## 1. 授权与适用范围

用户已确认：身高和体重必填，缺少任一项时禁止保存画像、生成计划和调整计划；允许删除旧画像、计划、训练记录、会话历史及关联快照和确认记录。

本轮执行任务五，并补齐任务二的残留接线。用户已授权真实模型测试，预算不设上限；已同意保留 rebuild-v1 至 rebuild-v5 原样，派生新版评测数据适配身高体重必填规则。允许 subagent 执行测试、构建、隔离应用启动、真实模型请求和业务接口联调。单个测试命令超时上限仍为 300s。实际结果按运行证据记录。

本契约由主会话冻结，作为本次跨任务对照依据。任务一将其同步到 PRODUCT.md 和既有设计契约。实施中遇到产品决策缺口须停止并联系主会话。

## 2. 完整画像数据契约

ProfileContent 保留现有八个字段，增加下列三个字段。完整 payload 共十一键，各键均必须存在，拒绝额外键。

| 字段 | wire 类型 | 校验与语义 |
|---|---|---|
| height_cm | number | 必填、非 null、有限正数；单位 cm，支持整数与小数 |
| body_weight_kg | number | 必填、非 null、有限正数；单位 kg，支持整数与小数 |
| body_weight_measured_on | string / null | 必须有键；有效 YYYY-MM-DD 日历日期，测量日期未知时值为 null |

六个文本字段仍为 string / null；两个限制列表仍为 string[] / null，原校验与目录引用规则保持。

- 数值拒绝布尔、字符串、0、负数和非有限值。采用现有严格 Pydantic 模型与前端数值校验原语。
- 保存明确单位换算后的数值。用户单位有歧义时澄清；API 仅接收 cm 和 kg 数值，单位写在字段名称中。
- 保留有效小数值；不增加产品尚未定义的精度截断及额外上限。
- 日期采用现有日期校验模式。明确相对日期使用既有 calculate_date 机制；未知日期保持 null。
- 身高体重属于用户事实，助手不得推断或编造。
- 新建画像缺少任一数值时先在对话收集，满足条件后创建完整快照。
- 更新保留未涉及字段。仅更新身高时保留体重及其日期；更新体重时日期必须对应本次测量，未提供本次测量日期则置 null。
- 用户提供历史体重且用途有歧义时澄清，不静默覆盖当前体重。
- get_profile 未建档的响应保持 version=null、content=null。

## 3. 后端写入与计划前置条件

### 3.1 画像

prepare_profile_update 与实际提交均执行完整画像校验。缺少必填数值或数值非法时拒绝创建或保存对应内容。

工具入参 schema 校验沿用既有 invalid_arguments 协议；业务服务内容校验复用 InvalidBusinessPayload / invalid_business_payload，并通过 errors[].path 提供字段路径。两层均拒绝非法画像，不新增保存入口。

完整展示、按钮授权、版本冲突、快照绑定、保存幂等及事务边界保持。

### 3.2 计划

- generation 与 adjustment 均要求存在已确认保存的合法完整画像，且使用真实画像版本。
- 约束覆盖生成新计划、修改尚未保存的生成建议、调整已保存计划及调整本次上传内容。
- 未确认的画像快照和聊天中的数值不能作为已保存画像依据。
- 准备和提交共用既有画像依据核验路径。提交前继续核验画像版本、当前计划和限制。
- 缺少画像时复用 ProfileRequired，code=profile_required、HTTP 409。消息明确生成和调整都需要已确认保存且包含身高体重的画像。
- 已存在画像的模型校验保证身高体重合法；不为非法旧数据引入降级或兼容。
- 纯计划录入 import 保持 PRODUCT.md 的无建档前置规则。模型不得用 import 绕过生成或调整的前置条件。
- 已保存确认的幂等查询继续返回原固定结果，保持现有重复确认语义。

## 4. 对话与前端

- 建档和画像更新先 get_profile，再保留原字段构造完整快照。
- 生成或调整请求缺少已保存画像时，收集身高体重与本次任务必需信息，等待用户点击画像快照确认。
- 画像确认保存后重新取得真实版本，再继续计划准备。
- 将规则同步到系统提示词的画像、生成、录入与调整相关段落，保持规则一致。
- ProfileContentWire 与 parseProfileContent 同步十一键契约，复用既有有限正数与日期校验函数。
- ProfileFields 在画像页和对话快照统一展示“身高”“体重”“体重测量日期”；数值标注 cm、kg。
- 测量日期为 null 时沿用缺失字段的“未知”展示。只读画像入口、现有确认操作和真实错误展示保持。
- 前端不新增装饰性文案或占位引导。

- 一次性清理旧画像、计划、训练记录、会话历史以及关联快照、确认和会话运行记录。通过业务库重置完成。
- 保留 backend/data/models.json、backend/data/auth.json、环境配置、动作目录及独立观测数据库。
- 会话原附件文件继续遵循 PRODUCT.md 的保留规则，本轮删除会话及业务记录。
- 操作前核对本仓库服务进程和数据库占用，确保写入停止。仅可处理确认属于本仓库应用的写入进程；无法确认时停止并报告阻塞。
- 处理该业务库的 SQLite -wal、-shm、-journal 文件。保留其他数据库及日志。
- 用户已授权丢弃旧业务数据。本轮不实现旧画像、旧快照及历史 payload 的迁移兼容。
- 为满足暂不启动应用的边界，清理完成状态可为“业务库及其 sidecar 已移除，待下次应用按现有迁移创建空库”。不得据此声称新应用已启动或业务验收通过。
- 记录删除路径、处理进程、文件状态与保留配置的完整性核对结果，不记录凭据内容。

## 6. 任务边界与执行顺序

| 任务 | 写入范围 | 完成定义 |
|---|---|---|
| 一：产品与接口契约同步 | PRODUCT.md、tmp/business、tmp/contracts、相关 tmp/design 文档 | 与本契约一致，无相互矛盾的现行字段或前置规则 |
| 二：后端实现 | backend/app、必要 backend/test 和 backend/evaluation 固定数据 | 模型、画像准备/提交、计划门禁和提示词接线；测试源码随改动同步，暂不运行 |
| 三：前端实现 | frontend/src、必要 frontend/scripts 固定数据 | wire 类型、严格解析、共用展示及对应检查源码同步，暂不运行 |
| 四：旧业务数据清理 | 指定本地业务库与 sidecar、忽略目录中的操作记录 | 安全停写并执行已授权清理，保留配置与其他数据；不启动应用 |

采用同一 cwd 串行执行，一次仅一个写入 agent。每个 child 使用 fresh context，直接读取本契约与交接文档，不 fork 主会话。

主会话维护本契约与交接状态。子任务只修改各自授权文件，遇到越界需求联系主会话。
