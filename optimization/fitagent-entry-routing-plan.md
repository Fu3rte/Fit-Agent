# 决策分层与入口路由设计

--作废-2026.10.16

数据结构见[入口路由契约](fitagent-entry-routing-contract.md)。

## 1. 数据流与职责

1. 后端从当前有效分支和业务库组装 `state`。
2. 分类器读取 `state` 与固定 `questions`，一次模型调用返回 `actions`。
3. 代码根据任务与交互类型生成提示词和工具策略。
4. 单个业务 Agent 执行 ReAct，读取事实、定位目标、整理参数和调用工具。
5. 用户点击指定快照的确认按钮，经独立 HTTP 接口保存，全程无需模型。

分类器与业务 Agent 共用运行开始时读取的 `ModelConfig`、取消信号和请求预算。

`state` 保留当前输入、相关历史、未完成任务、有效提案和必要业务摘要。身份、状态和准备类型来自后端真实数据；附件与引用保持数据身份。

`questions` 由代码固定维护，定义业务范围、交互类型和动作组织规则。业务参数由对应业务流程收集；任务或目标存在歧义时澄清。

分类器输出使用 Pydantic 严格校验。模型调用或校验失败时终止本次业务执行。

## 2. 运行生命周期

路由接入 `http.py` 的运行装配层，覆盖发送、编辑与重新生成，在首次业务模型请求前完成。

Steering 真正消费后，更新用户节点、业务日期和未完成任务，重新组装输入并分类。

工具结果续接和压缩恢复复用本轮路由。同一操作重试复用已有受理结果。

上下文投影从真实持久化分支重建，并应用本轮策略。专项系统规则随任务替换或移除，历史节点与确认绑定保持完整。

## 3. 提示词与工具策略

公共规则始终保留来源忠实性、医疗风险、器械与动作限制、附件安全和授权边界。

同一份策略用于模型请求投影、工具声明、执行白名单、预算计数和压缩输入。批次工具绑定使用对应用户节点与工具来源节点，越界调用由执行端拒绝。

任务能力：

- `profile`：画像读取、`prepare_profile_update`、结果状态查询，按需核实动作。
- `plan_import`：画像与当前计划依据、附件读取、`prepare_plan_import`，按需核实动作。
- `plan_generation`：画像准备流程、当前计划、近七日训练、可信日期、动作检索、`prepare_plan`。
- `plan_adjustment`：调整对象、画像、最近十条完整训练、动作检索、`prepare_plan_adjustment`，按需更新画像。
- `workout`：可信日期、当天记录、动作身份、`prepare_workout`、结果状态查询。
- `query`：画像、计划、训练、动作、提案与原操作状态的只读查询。
- `other`：公共规则与对话。

交互规则：

- `revise_pending`：读取真实提案，按业务类型和准备类型选择准备工具。生成建议的修改继续使用 `prepare_plan`。
- `cancel_pending`：提供提案读取和指定提案取消能力。
- `clarify`：询问歧义，目标明确前保持对应业务状态不变。

复合请求按用户依赖推进，合并完整工具依赖并固定声明顺序。依赖已保存事实的任务，必须读取真实保存结果。

## 4. 附件、取消与保存边界

纯附件仅授权完整读取本次全部附件。读取后澄清处理意图，等待用户文字明确要求；期间禁止业务准备、提案取消、保存与更新。

取消工具顺序执行，在同一数据库事务中：

- 核验目标归属当前会话与有效路径，处于 `pending`，完整展示已绑定且内容一致。
- 核验本次普通用户节点包含文字，时序满足展示早于请求、请求早于工具来源节点。
- 核验来源节点存在名称与参数匹配的取消调用。
- 检查目标没有已受理且正在处理的确认操作，再将指定快照置为 `invalidated`。

确认受理、保存与取消共用事务协调。已保存、处理中、失效、冲突、未展示和路径外目标按实际状态拒绝取消。

取消仅使指定草稿失效，保留已保存业务数据、其他提案和历史。恢复内容需重新准备、完整展示并等待按钮确认。

每个业务动作使用自身事务。后续任务失败或运行停止时，已提交的取消结果保持有效，分别报告各项实际结果。

运行期间沿用确认占用规则；终态刷新历史，失效提案移出待确认引用，旧卡片停止提供确认操作。

保存继续遵循 [PRODUCT.md](../PRODUCT.md) 的指定快照确认契约。

## 5. 预算与观测

入口调用单独记录用途，关联 `run_id`、用户节点、模型、题库与策略版本、结果、耗时和用量。

总耗时、模型调用数、tokens 和费用覆盖入口判定与完整业务执行。

对照评测保持公共用例、前置数据、模型配置、重复次数、缓存条件与统计口径可比，记录环境差异和有效样本数。

评测任务正确性、提案目标、业务成功率、授权边界、额外澄清次数、延迟分布、用量及缓存表现。新增路由专项用例单列，公共用例分母保持一致。
