# 前端 Stage 2 开发计划：计划启用闭环

> 状态：计划已制定，待用户确认后按本文件实施；确认前不开工、不改代码。
> 结项门槛：mock 上从「已建档、尚无计划」种子按第 7 节剧本完整走通计划生成、纠错、启用、替换、日程切换与安全阻断，并留证据。
> 本文件细化 [business-roadmap.md](business-roadmap.md) 阶段 2「计划启用闭环」，依赖 Stage 0 草稿公共流程与 Stage 1 已确认档案、限制语义。
> 后端计划域、日程与真实 Agent 接口尚未接入前端；本阶段只改 `frontend/`，全部业务链路在 mock 上演示。

## 1. 阶段目标

1. 从已确认档案生成一份可确认的 PPL 计划草稿，完整展示生效范围、处方、校准说明和具体日程；确认前正式计划与日程不变。
2. 确认后原子启用计划版本并生成 `[开始日期, 复核日期)` 内的日程；替换计划时同卡展示旧版未来未锁定日程取消与新版日程。
3. 在 `/profile` 只读查看当前计划及具体日程；计划修改仍只能从对话发起。
4. 使用计划提供训练指导前按最新限制复核整份计划；任一冲突即整份阻断，红旗症状独立阻断。
5. 继续复用 Stage 0 的纠错、确认、丢弃、幂等、stale、重算与恢复链路，不建立第二套计划事务。

## 3. 本阶段范围与已确认口径

### 3.1 动作目录与推荐候选

- 沿用后端 Stage 1 已核对的 24 项目录，不重新调研、不扩充动作集；24 项是候选目录，不是一份计划必须包含的动作数量。
- mock 只镜像计划生成所需的既有身份、器械、动作模式、记录类型与负重口径；真实后端 `recommendable` 标记不在本前端阶段修改。
- 本阶段 mock 的可推荐检查采用已确认最小标准：动作身份与来源已核对、动作处于 active、器械／记录／负重口径和动作模式完整。通过者才进入候选；生成时再按正式档案中的器械、具体动作限制和动作模式限制过滤。
- PPL 是可表示的首版模板，不写死为唯一契约结构，不建设模板插件系统。

### 3.2 无可信记录时的校准

- 不生成或暗示具体起始重量，也不按体重、估算 1RM 或默认杠重猜测。
- 草稿将对应动作标为「需要校准」，展示逐级试重步骤。
- 通过标准：动作稳定完成处方次数下限，且落在目标 RIR 区间。
- 停止条件：出现疼痛／红旗症状、动作明显失稳，或无法满足目标 RIR；停止后不继续给出加重处方。
- 本阶段空计划种子无可信训练记录，只验收校准路径；基于可信历史给负荷与渐进建议留到记录数据接入后的阶段 5。

### 3.3 候选日期

- 采用「Agent 先提出、用户可修改、确认后生效」，不是静默默认。
- Stage 2 mock 固定演示候选：mock 当前日期 `2026-09-10`，开始日期 `2026-09-14`，周一／周三／周五训练，复核日期 `2026-10-12`；生成 09-14 至 10-09 共 12 个日程，不生成 10-12 及以后日程。
- 该日期组合只服务本阶段确定性剧本，不建立覆盖任意频率的通用自动排程算法；真实 Agent 后续可提出其他明确候选，但必须在草稿中完整展示并由用户确认。

### 3.4 契约与 mock

- 计划草稿从「标题 + Diff」升级为结构化载荷：拟议完整计划版本、具体日程、生效范围、可选长期档案补丁、旧版日程取消清单及服务端派生 Diff。
- 计划动作补齐目录身份、所需器械、动作模式、组数、次数区间、目标 RIR、渐进方式与校准状态；计划日补齐预计时长。
- 增加具体日程查询形状：计划版本、训练日、日期、锁定／取消状态；不把日历休息日写成应训练日。
- 计划仍通过 `/api/profile` 的只读投影展示；是否可用于指导作为最新安全复核结果单独表达，不新增「部分可用」计划状态。

### 阶段交界

| 本阶段交付 | 后续阶段负责 |
|---|---|
| 当前计划版本、具体应训练日与安全复核投影 | Stage 3 当次安排、临时状态调整、实际训练及打卡 |
| 无可信记录的校准标记与操作说明 | Stage 5 基于可信历史的渐进、长期计划调整与复盘建议 |
| 计划替换、受限组合草稿与旧日程切换 | Stage 4 历史记录更正；Stage 5 从复盘发起新计划 |
| 红旗／限制对计划生成和指导的阻断 | 后续训练、接回环节继续在使用时复核，不重复实现规则 |

## 4. 明确不做

- 不接真实后端、真实模型或真实动作目录 API；不修改 `../backend/`、`../pre-prj/` 决策正本。
- 不做训练打卡、实际记录、当次安排接受、睡眠／疲劳状态调整（Stage 3）。
- 不做统计、基于历史表现自动加重、复盘或中断接回（Stage 5）。
- 不做复核日后的自动续期、自动跨周期切换或复杂周期阶段；该事项仍按 04 章保持未拍。
- 不实现完整计划编辑器、任意动作拖拽、模板插件、后台安全巡检或「计划部分可用」状态。
- 不导入媒体、不扩充 24 项目录、不新增依赖或测试框架。
- 不把 mock 中的可推荐检查声称为真实后端 `recommendable` 已更新，不把 mock 通过声称为真实链路通过。

## 5. 任务拆分与逐项验收

### F2-01：计划／日程契约与 mock 候选目录

- **工作**：扩展 `contract.ts` 的结构化计划草稿、计划动作、校准、日程、旧日程取消和安全复核投影；mock 镜像既有 24 项目录的必要字段并执行 3.1 的可推荐检查；保留契约为数据形状唯一来源。
- **依赖**：Stage 1 结项；本计划 3.1–3.3 已确认。
- **验收标准**：`tsc -b` 零错误；24 项身份与后端已拍清单一致，无第 25 项；计划与日程不再塞进文本 Diff；未受检或 inactive 动作不能进入计划候选。
- **验证方式**：类型检查 + 24 项名称／模式／器械对照探针。

### F2-02：计划生成与安全前置校验（mock）

- **工作**：从已建档、无红旗、尚无计划种子生成 PPL 草稿；按频率、每次时长、器械、具体动作限制、动作模式限制及同一训练日重复动作身份过滤／校验；跨训练日重复使用同一动作不自行判冲突；无可信记录统一走 3.2 校准；生成 3.3 的候选日期与 12 个具体日程。缺档案或存在红旗时不生成计划处方。
- **依赖**：F2-01。
- **验收标准**：计划只引用可推荐且条件匹配的目录动作；每周 3 个训练日、每次预计时长不超过档案 60 分钟；限制动作不进入草稿；红旗分支只建议线下专业评估；所有动作均不出现猜测重量。
- **验证方式**：第 7 节第 1–4、11 步。

### F2-03：结构化计划草稿卡与轻量纠错

- **工作**：草稿卡展示版本、生效范围、开始／复核日期、每周安排、动作顺序、组数、次数区间、目标 RIR、渐进、校准说明和具体日程；替换计划时展示旧版未来未锁定日程取消；支持日期／训练日、动作候选、组数、次数区间和 RIR 的轻量纠错，仍经 revise 使 revision+1；不提供任意模板或板块编辑器。
- **依赖**：F2-01、F2-02。
- **验收标准**：确认前正式计划与日程不变；纠错后结构化内容与 Diff 同步；不可推荐、器械不符、限制冲突、日期越界或同日重复动作在服务端校验中被拒绝，不能靠前端绕过。
- **验证方式**：第 7 节第 3–5 步。

### F2-04：计划启用、替换与原子日程切换

- **工作**：首次确认允许从无计划创建 v1；在一个 mock 事务中完成领域复查、计划版本追加并激活、`[开始日期, 复核日期)` 日程生成、草稿提交和 context_version+1。替换计划时归档旧版、保留历史，只取消旧版未来未锁定日程并写入新版日程；已锁定日程不动。支持「以后只能用哑铃」的受限组合草稿：长期器械补丁、新计划与日程一次确认、一次版本递增；「今天只能用哑铃」不写长期补丁。
- **依赖**：F2-03。
- **验收标准**：失败注入时档案、计划、旧／新日程、草稿状态和 context_version 全部不变；重复确认不重复建版本或日程；已提交幂等、已丢弃拒绝、stale→重算、revision 冲突均复用 Stage 0 行为。
- **验证方式**：第 7 节第 5–9 步。

### F2-05：当前计划、日程与使用时安全阻断

- **工作**：更新 `/profile` 当前计划卡，展示状态／版本／日期、处方、校准、具体日程及取消／锁定状态；确认后失效刷新。请求当前计划指导时按最新红旗与限制复核整份计划：任一动作或模式冲突即不给任何基于该计划的可执行处方，明确显示冲突与修订入口；旧计划和历史仍可查看，计划状态不伪造为「部分可用」。
- **依赖**：F2-02、F2-04。
- **验收标准**：空态→启用→替换展示一致；新增与任一计划动作冲突的限制后，请求任一训练日指导均被整份阻断；红旗独立阻断；页面没有直接编辑入口。
- **验证方式**：第 7 节第 6、10、11 步。

### F2-06：闭环演示与证据

- **工作**：按第 7 节完整走查并记录证据，包含正常、空数据、失败、幂等、stale、原子回滚和安全冲突分支。
- **依赖**：F2-01–05。
- **验收标准**：剧本全部通过；`npm run build` 零错误；证据完整且明确 mock 边界。
- **验证方式**：人工浏览器走查 + 协议探针 + 构建命令。

### 推荐执行顺序

F2-01 → F2-02 → F2-03 → F2-04 / F2-05 → F2-06。

## 6. 验证方式与证据要求

- 全部在 mock 上验证；`npm run build`（`tsc -b && vite build`）零错误，不引入浏览器 E2E 或组件测试框架。
- 协议探针至少覆盖：24 项一致性、日期边界、确认前隔离、原子切换、幂等、stale／revision、限制／红旗阻断。
- 每项记录：任务编号、平台、代码版本、步骤／命令、预期／实际、证据路径、未覆盖部分，沿用 Stage 0/1 格式。
- 本阶段不得标为已验证：真实计划域事务、真实动作 `recommendable` 更新、真实 Agent 生成质量、真实数据库日程锁定、复核日后续期。
- mock 通过不代表真实链路通过。

## 7. 阶段闭环演示剧本（结项门槛）

前置：Stage 0/1 已结项；`npm run dev`；控制端点重置为「已配置、已建档、无红旗、尚无计划、无可信训练记录」种子，mock 日期为 `2026-09-10`。

1. **空计划检查**：`/profile` 展示完整档案、限制与「尚无计划」；无直接编辑入口。
2. **提出候选**：在对话请求生成计划 → Agent 提出 09-14 开始、周一／三／五、10-12 复核的候选并生成一份结构化计划草稿。
3. **处方与校准**：核对 PPL 动作均来自已确认 24 项且符合器械／限制；展示动作顺序、组次、RIR、渐进及「需要校准」；无任何猜测起始重量。
4. **日程边界**：草稿展示 09-14 至 10-09 共 12 个应训练日；休息日、10-12 及以后不生成名额。
5. **内联纠错与确认前隔离**：修改候选训练日或关键处方字段 → revise 后 revision+1、Diff 更新；确认前 `/profile` 仍无正式计划。
6. **首次启用**：确认草稿 → toast → context_version+1 → `/profile` 展示 v1、处方与 12 个日程；刷新后状态一致；重复确认幂等且不重复生成日程。
7. **替换与日程取消预览**：发起长期调整「以后只能用哑铃」→ 一张组合草稿展示档案器械补丁、新计划 Diff、旧版未来未锁定日程取消和新版日程；正式档案与 v1 在确认前不变。
8. **原子切换**：确认组合草稿 → 档案补丁、v2、新日程和旧日程取消同时生效，context_version 仅 +1；旧 v1 仍保留。故障注入后重做一次，验证任一步失败全部回滚。
9. **公共冲突分支**：制造 revision 冲突并确认 → `draft_modified`；推进 context_version → `draft_stale` → 一键重算 → 新旧 Diff → 再确认；丢弃草稿后确认被拒。
10. **限制冲突整份阻断**：经 Stage 1 链路确认新增一个命中当前计划的具体动作或动作模式限制 → 再请求任一训练日指导 → 整份计划明确阻断，不输出其余「未冲突」动作处方；旧计划仍可查看，并引导从对话发起修订草稿。
11. **红旗与非法纠错**：红旗种子请求计划／指导 → 仅建议线下专业评估、无计划草稿；另验证把限制动作、器械不符动作或同日重复动作改入草稿时服务端拒绝，正式数据不变。
12. **恢复与收尾**：待确认时刷新恢复草稿当前状态；确认后刷新恢复正式计划／日程；`npm run build` 零错误，证据归档。

## 8. 已拍与条件性待拍事项

本阶段已拍（2026-09-10）：

- 复用既有 24 项 `exercises-dataset` 精选目录；通过身份／来源、active、器械、记录／负重口径与动作模式完整性检查后可进入 mock 推荐候选，再按档案器械和限制过滤。
- 无可信记录采用非百分比校准：稳定完成次数下限且符合目标 RIR 即通过；疼痛／红旗、动作失稳或无法满足目标 RIR 即停止。

- 若实现需要把「同一训练日相同动作身份重复」扩展为跨日重复、动作模式重复或训练量上限等新规则，停下列选项等拍板。
