## 1. 阶段目标

1. 契约（`src/lib/contract.ts`）从草案升级为对齐架构正本的 v1 基线：SSE 事件全集、Run 状态与显示映射、错误码、草稿生命周期（纠错/确认/丢弃/修订版本）、恢复查询端点一次定型。
2. mock 服务器同步改造：断线不重放、heartbeat、Run 状态机、部分回答（关键路径建模）、草稿修订与丢弃语义、场景与故障注入控制。
3. 前端补齐三块：对话运行状态呈现（08 8.8 显示映射）、断线/刷新查询恢复全套（08 8.7 规则）、草稿公共流程（纠错走业务接口、丢弃、幂等、stale→重算、修订校验）。
4. 沉淀可重复的人工演示剧本与接入点对照表，为阶段 1–5 每阶段「完整跑通业务闭环」提供稳定公共底座。

## 5. 任务拆分与逐项验收

### F0-01：契约 v1 修订（contract.ts 定型）

- **工作**：
  - SSE 事件全集按 08 8.7 收敛：`run.started/completed/cancelled/failed`（failed 附可理解原因 error_code）、`message.delta`、`draft.proposed`（引用草稿身份与修订版本）、`context.compacting` / `context.compacted`（压缩两态）、`heartbeat`（15s，不入库、不分配 ID、不显示在聊天里）。移除无正本依据的通用 `error` 业务事件；移除 Last-Event-ID 补读注释与查询参数。
  - 新增 `RunStatus`（五种）与 8.8 显示映射说明；`ErrorCode` 增补 `interrupted_by_restart`、`draft_modified`（确认时修订不匹配）。
  - 草稿：`Draft` 增加 `revision`；`DraftStatus` 增加 `discarded`；`ConfirmRequest` 携带所见修订版本；新增纠错（Revise）与丢弃端点、`GET /api/runs/active`（全局活跃 Run：状态 + 已保存部分回答 + 关联草稿当前状态）、`GET /api/sessions/:id/drafts`（会话草稿当前状态列表）。
  - `ChatMessage` 增加可选 `evidence` 字段（依据与说明：来源/引用/简短说明，随消息携带、不独立流式化）。
  - 每处新类型注明正本出处（08/01 章节号）。
- **依赖**：无。
- **验收标准**：契约与 08 8.7/8.8、01 1.2–1.6 逐条对应，无 Last-Event-ID/重放/补读残留；`tsc -b` 零错误。
- **验证方式**：类型检查 + 对照清单逐条核对。

### F0-02：mock 服务器改造

- **工作**：SseHub 移除事件缓冲与重放，heartbeat 改命名事件；Run 状态机补 pending 阶段（POST /api/runs 先 pending，转 running 时发 run.started），取消仅 pending/running 可转；部分回答关键路径建模（已流出整段记为已保存，run 查询返回已保存文本与状态）；run.failed 支持 `interrupted_by_restart`；草稿纠错端点生成 revision+1 并校验待确认状态；确认按 01 顺序校验（已提交幂等 → 已丢弃拒绝 → context_version → 修订版本）；丢弃端点；runs/active 与会话草稿查询；dev-only 控制端点（重置种子场景、注入 run 失败/重启中断、挂起事件以演练 45s 转查询），不进契约文件。
- **依赖**：F0-01。
- **验收标准**：剧本所需全部状态可复现（failed/interrupted_by_restart、压缩两态、修订冲突、已丢弃拒绝确认、45s 无事件）；幂等/stale/修订/丢弃行为与 01 一致；无重放路径残留。
- **验证方式**：按第 7 节剧本逐条操作 + 控制端点触发异常分支。

### F0-03：对话运行状态（前端）

- **工作**：8.8 显示映射统一（处理中/已完成/已取消/未完成；pending 与 running 统一映射「处理中」，可细分受理中/执行中的次要文案，不新造状态语义）；failed 显示「未完成」+中断原因（`interrupted_by_restart` 显示服务重启中断文案），保留已保存内容和草稿，不自动恢复执行；手动重试 = 以新 client_request_id 重新发送；压缩两态呈现（快速完成 toast 3s 消失；明显等待常驻「正在整理上下文」至结束撤下；可自动恢复的失败不报错）；跨会话运行状态条与 409 busy toast 保持。
- **依赖**：F0-01、F0-02。
- **验收标准**：五种状态均有对应展示且文案符合 8.8；取消/失败后中断前文本保留并标明「输出未完成」。
- **验证方式**：剧本第 3、4、6 步。

### F0-04：SSE 订阅治理与查询恢复（前端）

- **工作**：单例 EventSource 保留；heartbeat 更新最后接收时间；连续 45s 无事件或连接 error → 主动 close() 转查询；查询失败 1/2/4/8/15s 有界退避（上限 15s），成功恢复正常间隔；断线仅提示「连接中断，正在恢复」，不取消、不重跑、不判失败；刷新/进入页面查询 `GET /api/runs/active`，活跃 Run 转轮询至终态，本次不接回 SSE；恢复渲染已保存部分 + 未完成标记，不重复拼接；终态/页面卸载关闭连接清理计时器；visibilitychange 恢复可见立即检查；草稿卡按会话草稿查询恢复当前状态。

## 7. 阶段闭环演示剧本（结项门槛）

前置：本计划经用户确认；`npm run dev`（mock 模式），记录代码版本。

1. **启动与配置链路**：五页可达、侧栏会话、主题切换；未配置 Key → 对话页配置指引空态 → 设置页录入 Key → 返回对话页可输入。
2. **发起与流式**：发送消息 → 乐观气泡 → 处理中 → run.started → delta 流式 → run.completed → 完整消息落列表、草稿卡出现。
3. **取消**：再次发送，流式中点「停止」→ run.cancelled，显示「已取消」，已流出文本保留并标「输出未完成」，全局可再次发送。
4. **失败与中断**：控制端点注入 run.failed（含 `interrupted_by_restart`）→ 显示「未完成」+中断原因，保留已保存内容和草稿；手动重试创建新 Run。
5. **断线恢复**：流式中刷新页面 → 「连接中断，正在恢复」→ 查询活跃 Run 转轮询 → 恢复已保存部分（未完成标记）→ 完成后消息完整、草稿卡按查询恢复；不重复拼接、不重放历史通知、不重跑。
6. **45s 转查询**：控制端点挂起事件 ≥45s（或注入 error）→ EventSource 自动关闭转查询，轮询至终态。
7. **确认与幂等**：确认采纳 → toast + 看板数据刷新 → 再次确认同草稿 → 幂等返回原结果。
8. **stale 与重算**：确认草稿 A → 经控制端点或另一确认推进 context_version → 再确认 A → 409 draft_stale → 一键重算 → 新草稿 + 新旧 Diff → 再次确认生效。
9. **修订与丢弃**：纠错字段 → 纠错接口 revision+1、Diff 更新；制造修订冲突（draft_modified）→ 提示并刷新草稿；丢弃 pending 草稿 → 已丢弃态 → 再确认被拒。
10. **收尾**：`npm run build` 零错误；证据按第 6 节格式归档。
