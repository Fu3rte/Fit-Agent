## 1. 阶段目标

1. **确定性统计只读消费**：`/review` 与对话中的完成率、三桶、PR、`data_updated_at` 一律由 mock 服务端现算；前端不重算、不缓存第二份派生数值（沿用 `DATA_QUERY_KEYS` 失效刷新）。
2. **复盘仅显式请求生成**：用户在对话明确要求生成／重新生成复盘，或从 `/review`「在对话中生成复盘」入口预填跳转后发送；无定时、无按周自动（06 6.4、Q3=B、存档 B1）。
3. **模型／脚本只写解释、不得改写数值**：mock 生成流程先冻结当前统计与来源修订快照，正文中的数字必须逐字来自冻结事实；保存时追加不覆盖旧正文（对齐 S4-08／`ReviewStore` 语义）。
4. **旧复盘不被静默改写**：依据变化时标记 stale，徽章文案沿用「依据已变更·可重新生成」；正文与 `generated_at` 保持不变，直至用户显式重新生成并确认新稿。
5. **复盘建议不自动生效**：Agent／脚本给出的后续安排或新计划建议，只在用户明确继续后进入既有草稿链路；确认前正式计划、日程与业务版本不变。
6. **后续调整走同一确认链路**：当次安排调整、长期计划修订、新计划启用复用 Stage 2–4 的草稿 → revise → confirm／discard、幂等、失败回滚、stale→recalc；不建第二套提交路径。
7. **B 档并入（改拍）**：渐进／负荷建议、中断接回、最低训练版已并入本阶段为 F5-05／F5-06（2026-09-13 协议级完成）。

## 3. 本阶段范围与已确认口径

### 3.1 复盘生成（显式、可追加）

- 触发（2026-09-13 owner 拍：**仅对话剧本**，无 dev 桥）：
  1. 对话中用户明确要求「生成／重新生成／更新复盘」；
  2. `/review`「在对话中生成复盘」→ 跳转对话并预填请求文案，用户发送后等价于 1。
- 生成前 mock 冻结：当前计划版本下的完成率（Wn）、三桶、PR、`data_updated_at`、相关来源修订 id 列表；冻结结果写入该次复盘的依据快照。
- 正文：mock 以确定性模板从冻结事实渲染 Markdown 解释（表现摘要、缺失信息提示、下一步建议的**文本**）；**不得**改写或编造冻结之外的数字；建议文案本身不落业务草稿。
- 保存：追加一条复盘记录（正文、快照、来源、`generated_at`）；不覆盖旧条目；保存不推进 `context_version`（与后端 ReviewStore 对齐）。
- 展示：`/review` **只展示最新一条**（2026-09-13 owner 拍）；依据变化时该条 `stale=true`，徽章「依据已变更·可重新生成」；**不做** UI 历史追溯（存储仍 append-only，探针可读回）。
- 空数据：无正式有效记录或统计分母为零时，允许生成「无可复盘事实」说明稿或明确拒绝并引导先打卡；**不得**编造完成率或 PR。

### 3.2 重新生成

- 仅在用户再次显式请求时进行；生成新追加条，旧条与旧 `generated_at` 不变。
- 重新生成前若业务版本相对某条旧复盘的来源已变化，该旧条保持 stale 直至被新条替换为「最新展示」——新条基于**当下冻结**生成，不继承旧 stale 状态的正文。

### 3.3 复盘后的后续安排／新计划

- 复盘正文末尾的「下一步建议」只作为对话建议文本；用户回复确认意图后才进入草稿：
  - **当次／短期安排**：走既有安排草稿链路（Stage 3）；
  - **长期计划修订／新计划**：走既有计划草稿链路（Stage 2），含旧版未来未锁定日程取消展示与一次确认原子切换。
- 确认前正式计划／日程／安排不变；失败注入整份回滚；重复确认幂等。
- 不得因为「复盘里写了建议」而自动 confirm、自动改档案或自动换计划。

### 3.4 展示与信息架构

- 仍为五页，不新增路由；复盘沉淀在 `/review`，生成入口在对话。
- `/review` 与 `/records`、`/profile` 保持只读；变更仍从对话发起。
- 用语沿用：「符合目标／未符合／待补全」「暂无」完成率；无 RIR 缩写作为主文案。
- Markdown 渲染沿用白名单（存档 A3），防注入。

### 3.5 契约、mock 与公共链路

- 契约先行（D1A）：形状唯一来源 `src/lib/contract.ts`。存储侧可 append-only；**UI 与 `GET /api/review` 最新投影只消费最新一条**（2026-09-13 拍）；字段拼写按既有命名约定由实施者定，语义按 06 6.4／S4-08；**不得**为演示新造未拍业务端点或错误码。
- mock 生成走**对话剧本**（无 dev 桥）；查询沿用 `GET /api/review` 最新条；请求幂等键若需要则对齐 `client_request_id` 既有模式。
- 复用：草稿 confirm／discard／失败注入／stale→recalc／查询恢复；不建第二套事务。
- mock 控制面沿用 default／empty 种子与 fail-next，仅扩展到复盘生成保存失败注入。

### 3.6 演示种子（沿用 Stage 4 §3.6，不重设）

mock 日期 `2026-09-11`；default 种子：W1 2/3、W2 1/3、三桶 1/1/1、PR 卧推 80×8、复盘已有正文且 `stale=true`（mock 时钟晚于生成时间）。

本阶段在此种子上演示：显式生成新复盘（基于现算统计）→ 展示最新条 → 更正／作废后再生成或看 stale → 复盘后提出后续调整草稿。期望值由 mock 现算给出。

## 4. 明确不做

- 不接真实后端、真实模型或真实 Agent；不修改 `../backend/`、`../pre-prj/` 决策正本；不引入新依赖、测试框架或浏览器 E2E（存档 B6）。
- 不做定时／按周自动复盘；不做复盘正文的前端或 mock「第二套数值计算」。
- 不把复盘建议自动变成已确认计划／安排／档案。
- 不新增独立复盘详情页或第六页路由。
- 不做真实 Provider 测评（09 章 pass³／裁判校准）、Windows 验收声明。
- 不做交接 F1／F5–F9 端点拆分；不把 mock 端点声称为真实后端已交付。
- 不做**自动**基于历史的加重建议、中断后台检测推送、7 天阈值的医学宣称；B 档只做对话显式触发的接回评估与负荷建议草稿。
- 校准「通过标准和停止条件」的**具体医学／训练阈值**若未另拍，mock 只沿用 Stage 3 D3 已拍口径（次数下限；RIR 非硬性），不发明新阈值。
- 病后未获专业允许的处置在 §8 拍板前：mock **只转介／建议休息**，不生成最低活动建议处方（防 PRD 冲突未调和就实施）。

### F5-05：中断接回与最低训练版 —— **已完成（协议级，2026-09-13）**

- **依据**：04 §4.6、PRD §5.12；回归期统计见 06 §6；Stage 3 已拍「明显状态差」最低版归本档。
- **工作**（对话剧本，无后台检测推送）：
  1. **触发**：① 显式意图「重新开始／中断回归／接回」；② 用户发起今日训练时，若距最近已确认训练 **≥7 天**，仅提示确认是否中断，**确认后**才进接回评估（不自动改计划）。无已确认记录 → 不判中断，走既有校准路径。
  2. **评估输入**（复用，不新造概念）：中断时长、可选原因、档案身体情况（读取时分类）、时间／器械是否变化。
  3. **处置四结果**：正常接回／降级接回／最低任务／建议休息或线下专业评估。红旗直接第四档，接回无权解除红旗。
  4. **三档方案**（草稿卡，新计划版本，不静默覆盖）：正常=原结构+铁律定负荷；降级=主项更保守且 −1 组；最低=启动活动+一个主要动作模式，约 10–20 分钟。前三档附未来 3–7 天简单日程。
  5. **铁律**：不补课、不惩罚性训练；不照搬中断前重量（最近确认记录为上限保守降载；无记录按 D3 校准）；确认走既有 plan 草稿事务；失败回滚、幂等。
  6. **回归期**：接回版本生效后的训练记录标记 `回归期`；不进常规对比与 PR；统计仍展示工作组。恢复常规=用户经复盘确认后**新版本**启用（不重激活旧版）。
  7. **病后**：未明确「已获专业允许」→ 只转介／休息，不生成最低活动建议。
