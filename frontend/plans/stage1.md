# 前端 Stage 1 开发计划：建档闭环

> 状态：已实施并通过阶段验收（2026-09-10）；实现与验收证据见 [stage1-evidence.md](stage1-evidence.md)。
> 结项门槛：mock 上从全新空种子按第 7 节剧本完整走通一次建档业务闭环并留证据（含正常、缺失追问、红旗、失败与冲突分支）。
> 本文件细化 `frontend/plans/business-roadmap.md` 阶段 1「建档闭环」，依赖 Stage 0 契约 v1 与 mock 底座（运行状态/查询恢复/草稿公共流程/场景种子机制）。
> 后端对应接口（档案域、应用层事务）均未实现；本阶段全部工作在 mock 上进行。

## 1. 阶段目标

1. 交付第一个业务纵向闭环：未建档空态引导 → 对话收集条件（缺失不编造）→ 结构化档案草稿 → 纠错、确认 → 档案与限制页更新。
2. 安全症状分支可演示：建议线下专业评估、报告原文记入档案草稿；不生成训练建议。
3. 全部复用 Stage 0 草稿公共流程（纠错/确认/丢弃/重算/幂等/恢复），不另建第二套确认链路。

## 2. 来源依据

| 依据 | 本阶段采用的约束 |
|---|---|
| [PRD](../../pre-prj/PRD.md) §5.2 | 对话是唯一建档入口，不提供独立表单；建档信息六类（目标与经验、每周频率、单次时长、可用器械、已知动作限制、当前身体状态与红旗症状）；缺失继续询问不补造；红旗症状不生成常规处方并建议线下专业评估；Agent 不诊断、不自动增删永久禁忌 |
| [02 档案与安全限制](../../pre-prj/architecture/02-profile-security.md) 2.1–2.3 | 建档通过对话进行；档案承载上述事实（2026-09-10 合并后为八项：合并后的身体情况与必填体重）；限制分具体动作与动作模式两种粒度，经确认长期保留；红旗独立阻断、不能由 Agent 解除 |
| [01 共用事务](../../pre-prj/architecture/01-shared-transaction.md) | 草稿机制、确认事务、context_version 沿用，不因建档新增例外 |
| [前端决策存档](../../pre-prj/architecture-archive/frontend-presentation-decisions.md) | B4（建档对话唯一入口，复用草稿确认闭环）；B1（/profile 页内容）；草稿卡必含元素 |
| [stage0](stage0.md) | 契约 v1、mock 底座、演示剧本与证据格式沿用 |

## 3. 本阶段范围

- 契约微调（仅档案域字段，不动 Stage 0 公共语义）：
  - `Profile` 补齐六类事实，并保留必填体重（2026-09-10 拍板：原「当前身体状态」与「红旗症状」合并为单一「身体情况」`body_conditions`，档案事实八项；`body_weight_kg` 未提供时继续追问，不生成完整档案草稿）。
  - `Restriction` 增加粒度字段（具体动作 / 动作模式）；只保存当前有效限制，不新增观察中／暂禁／永久等业务状态。「暂禁」仅为红色徽章展示文案，解除通过对话草稿确认后的删除完成。
  - `ProfileDraftPayload` 从「title + diff」改为结构化档案字段载荷；diff 由 mock 从新旧档案对比派生。
  - 未建档表示：`/api/profile` 在未建档时的形状（空态字段，具体形状由实现定，契约注释注明）。
- mock：全新空种子场景（无档案/限制/计划/记录，复用 Stage 0 控制端点切换）；建档对话剧本（多轮收集、缺失追问、红旗分支、生成档案草稿）；档案确认事务（写入档案+限制、context_version+1、统计重算空态）。
- 前端：档案草稿卡结构化分支；未建档空态（/profile 与对话页）；建档后 /profile 展示（档案卡 + 限制卡 + 「尚无计划」占位）。
- 阶段闭环演示剧本与证据。

### 阶段交界

| 本阶段交付 | 后续阶段负责 |
|---|---|
| 档案 + 限制正式数据（mock）与 context_version 递增 | 阶段 2 计划生成以档案/限制为输入；使用时安全复核阻断 |
| 红旗信息入档 +「建议线下专业评估」呈现 | 红旗对计划、指导、接回的阻断验收在阶段 2–4 对应环节 |
| 限制增删走对话草稿 | 后续阶段继续复用同一链路，页面保持无直接编辑入口 |

## 4. 明确不做

- 不做计划生成/启用（阶段 2）；不做限制与计划的冲突阻断演示（阶段 2 使用时复核）。
- 不做档案/限制页任何直接编辑入口（02：增删只能经对话草稿确认）。
- 不实现红旗解除流程（Agent 无权解除；本阶段仅收集与展示）。
- 不接真实后端与真实模型；不引入新依赖；不建测试框架（存档 B6）。
- 不扩展 Stage 0 已定型的公共契约语义（新增字段仅限档案域）；不改决策正本。

## 5. 任务拆分与逐项验收

### F1-01：契约微调与空种子

- **工作**：上述档案域契约微调；mock 空种子场景接入 Stage 0 控制端点。
- **依赖**：Stage 0 结项。
- **验收标准**：`tsc -b` 零错误；空种子下五页无崩坏、未建档态可查询；新字段注明 PRD/02 出处。
- **验证方式**：类型检查 + 空种子启动走查。

### F1-02：建档对话剧本（mock）

- **工作**：多轮收集剧本（信息分批给 → 逐项追问缺失项，不编造默认值；体重必填，动作限制／身体情况的「未知」不得自动写成「无」；2026-09-10 拍板：身体情况一次覆盖当前不适、是否影响动作与六类安全症状，不单独追问动作限制）；信息齐备生成档案草稿（profile_update，结构化载荷 + 派生 diff）；安全症状分支仅识别正本明确列出的症状（命中清单 → 回复建议线下专业评估、报告原文记入草稿身体情况字段，无训练建议；清单外症状继续澄清，不判定安全）；限制收集支持具体动作与动作模式两种粒度，只表达当前有效限制；打卡类请求仅说明该能力不在本阶段开放，不生成记录草稿，也不宣称建立计划是记录训练的业务前提。
- **依赖**：F1-01。
- **验收标准**：剧本分支可复现；缺失信息时追问而非补造；红旗时不生成训练建议；清单外症状不被判定为安全；限制粒度正确落草稿且不引入新的限制状态语义。
- **验证方式**：按第 7 节剧本 3–5 步操作。

### F1-03：档案草稿卡与确认

- **工作**：结构化档案草稿卡（六类字段 + 必填体重内联纠错：选择、数字、器械/限制列表增删）；纠错走纠错业务接口（Stage 0 流程，revision+1）；确认 → 档案+限制写入、context_version+1、看板失效刷新；幂等/stale/丢弃/重算/恢复复用 Stage 0，不为档案写第二套逻辑。
- **依赖**：F1-02。
- **验收标准**：确认前正式档案不变；纠错后展示与 Diff 实时更新；确认后档案页与草稿状态一致；草稿卡必含元素齐全。
- **验证方式**：剧本第 6–8 步。

### F1-04：未建档空态与档案页更新

- **工作**：/profile 未建档引导卡（对话是唯一建档入口 + 跳转对话页）；对话页未建档引导文案；建档后 /profile 档案卡 + 限制卡（当前有效限制使用红色「暂禁」展示徽章；该文案不代表新增限制状态或自动到期机制）+「尚无计划」占位；页脚「变更请到对话页发起」。
- **依赖**：F1-01（可与 F1-02 并行）。
- **验收标准**：空态 → 建档 → 更新全流程展示正确；页面无直接编辑入口。
- **验证方式**：剧本第 1、7 步。

### F1-05：闭环演示与证据

- **工作**：按第 7 节剧本完整走查并记录证据。
- **依赖**：F1-03、F1-04。
- **验收标准**：剧本全步骤通过；`npm run build` 零错误；证据完整。
- **验证方式**：人工走查 + 构建命令。

### 推荐执行顺序

F1-01 → F1-02 / F1-04（并行）→ F1-03 → F1-05。

## 6. 验证方式与证据要求

- 全部在 mock 上人工走查；`npm run build` 零错误；不引入自动化测试框架（存档 B6）。
- 每项记录：任务编号、平台、代码版本、步骤/命令、预期/实际、证据路径、未覆盖部分（沿用 Stage 0 格式）。
- 本阶段不验证：真实档案域后端、红旗阻断对计划/指导的实际效果、限制与计划冲突复核；不得标为已通过。
- mock 通过不代表真实链路通过。

## 7. 阶段闭环演示剧本（结项门槛）

前置：Stage 0 已结项；`npm run dev`，控制端点重置为空种子。

1. **空态检查**：五页无崩坏；/profile 显示建档引导；对话页未建档引导文案；记录/统计/复盘空态文案正常。
2. **配置**：设置页录入 Key（沿用 Stage 0 流程）→ 回对话页可输入。
3. **缺失追问**：只提供部分信息（如仅目标）→ Agent 逐项追问经验、频率、时长、器械、体重、动作限制与身体情况；未知不得自动写成「无」。（2026-09-10 拍板：不单独追问动作限制；身体情况一次覆盖当前不适、是否影响动作与六类安全症状，未命中清单的内容同样记入。）
4. **安全症状分支**：仍有建档信息缺失时报告正本明确列出的安全症状（如胸部异常不适或锐痛）→ 回复建议线下专业评估、报告原文进入待生成档案的身体情况字段，无任何训练建议；清单外症状只继续澄清，不判定安全。
5. **齐备出稿**：补齐其余信息（含体重及一条身体情况报告，如「深蹲时膝盖锐痛」，由系统提议限制并经确认）→ 只生成一份档案草稿卡，展示六类结构化事实、体重、身体情况与 Diff。
6. **内联纠错**：修改频率、增删器械、增删限制 → 纠错接口 revision+1、Diff 实时更新。
7. **确认与更新**：确认前回看 /profile 数据未变 → 确认采纳 → toast → /profile 档案卡 + 限制卡（红色徽章）+「尚无计划」占位。
8. **幂等与丢弃**：再次确认同草稿 → 幂等返回原结果；再发一次变更请求生成新草稿 → 丢弃 → 已丢弃态 → 确认被拒。
9. **恢复一致性**：草稿待确认时刷新页面 → 草稿卡按查询恢复；确认后刷新 → committed 态与档案页一致。
10. **stale 与重算**：确认前推进 context_version（另一确认或控制端点）→ draft_stale 拦截 → 一键重算 → 新草稿 + 新旧 Diff → 再次确认生效。
11. **收尾**：`npm run build` 零错误；证据归档。

## 8. 已拍与条件性待拍事项

本阶段已拍（2026-09-09）：

- `body_weight_kg` 为建档必填；缺失时继续追问。
- 限制只保存当前有效项及具体动作／动作模式粒度；不新增观察中／暂禁／永久等状态语义，「暂禁」仅为展示文案。
- 红旗清单外症状采用最小范围：继续澄清，不判定安全，不自行扩充医学规则。

2026-09-10 追加已拍（正本见 `pre-prj/stage/body-conditions-merge-plan.md`）：

- 档案事实八项；「当前身体状态」与「红旗症状」合并为单一 `body_conditions`，保留三态；分类移到读取时。
- 首次建档不单独追问动作限制；结论由身体情况推出（`action_restrictions` 仍必填）。
- 面向用户不显示「红旗」术语，改用具体症状询问；草稿卡展示规则 3a／3b（3b 为读取时派生展示）。
- **本阶段交付代码与证据仍为合并前的九字段结构**（实现已撤回、待重新实施）；上述口径为重新实施的目标契约，重施后需重新取证。

当前无其余前置待拍。条件性事项：
