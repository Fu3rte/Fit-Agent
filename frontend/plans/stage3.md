## 1. 阶段目标

1. 查看当前计划的当次安排状态：某应训练日「尚无安排 / 已接受安排（是否调整、接受时间）」；对话请求指导时，已接受安排优先于原计划处方。
2. 当次临时调整只走已拍两种（减少组数、目标 RIR +1）且必须说明原因；接受即落盘（真实 `accepted_at`、`context_version` 恰好 +1、幂等），不改长期计划与其余日程；「明显状态差」仅建议休息文案，不生成结构化处方。
3. 自然语言打卡整理为结构化记录草稿：逐组事实可空字段不编造、热身摘要保留原文、人工辅助异常申报、歧义先询问；确认后落正式训练记录。
4. 记录页能区分**原计划、接受安排、实际记录**三份事实；组级三桶按当次安排快照判定，无对照安排不判定、单独展示实际表现。
5. 统计页完成率（Wn）、三桶、PR 全部由 mock 服务端现算并在确认后更新；支持待补全记录、无安排训练与同日多练的完整口径。
6. 继续复用 Stage 0–2 的纠错、确认、丢弃、幂等、stale、重算与恢复链路，不建第二套事务。

## 3. 本阶段范围与已确认口径

### 3.1 当次安排

- 「当次安排」不限于今天：可对未来的应训练日制定安排，也可训练结束后反馈再定后续安排；每份安排绑定 `scheduled_session_id` + 计划版本 + 训练日（04 4.3）。
- 临时调整只有两种已拍字段：减少 `work_sets`、上调 `target_rir`；调整与原计划有差异时 `adjustment_reason` 必填非空白；不能加组、降 RIR、增删动作或改绑定（归属变更走新草稿）。
- 状态调整表三档演示口径（已拍 2026-09-12）：「正常」按原计划回复、不出草稿；「一般状态差」出两种调整草稿；「明显状态差」仅回复「建议休息」文案、不生成任何结构化草稿；「最低训练版」不做（归接回阶段一并拍）；红旗仅阻断并建议线下专业评估。
- 接受即落盘：确认安排草稿写入完整目标快照与真实 `accepted_at`，与草稿提交、领域复核、`context_version` +1 同事务；重复确认幂等返回原凭据；不得倒填。
- 日程锁定 ≠ 处方锁定：当日日程即使已按日期规则锁定，执行前仍可确认减组；接受后事后不可倒改当次目标。
- 使用时安全复核：请求任一训练日指导（含已接受安排）前按最新红旗与限制复核；任一冲突整份阻断、红旗独立阻断；阻断不妨碍记录实际训练。

### 3.2 打卡事实边界

- 记录草稿承载结构化事实：动作（目录身份）、逐组 `SetFacts`（负重原文 + 单位、次数/时长、可空 RIR/质量/辅助）、热身摘要原文；「今天」等相对日期解析为具体日期展示。
- 可空字段一律「未明确」，不默认、不推导：未报 RIR 保持空、未提辅助显示「无辅助」待确认、「力竭」不折算 RIR；负数 / 非有限 RIR 不通过校验。
- 归属歧义先询问：同日「补充上一练还是新增一练」在草稿生成前询问，不自动拆分；同日多练各自身份，补充同次不增身份。
- 计划关联可空且只由草稿显式携带 `arrangement_revision_id`，不从日期推断；无安排训练不强套计划、不补造目标，仅作历史表现数据。
- 必填事实不完整时允许确认 `incomplete` 修订（后端 D8）：状态展示「待补全」，不进 PR 与完成率分子；**补全经更正修订转 valid 归 Stage 4**，本阶段不做补全交互。

### 3.3 统计与判定口径

- 完成率按计划周 Wn 现算：分母 = 该版本 `[starts_on, review_on)` 内 `scheduled_on <= 业务日期` 且未取消的应训练日程（漏练保留、休息日与未来日不进）；分子 = 关联到该日程的正式有效记录（明确完成 + 至少一个实际工作组），同一安排最多贡献一次；分母为零显示「暂无」。
- 三桶判定基准是**当次安排快照**，不是计划版本；判定顺序：已知未满足 → 未符合；否则缺必要判定信息 → 待补全；全部满足 → 符合。无对照安排的记录不进三桶，单独展示实际表现。
- PR 排除集：草稿、整条 incomplete、作废、旧修订、热身组、辅助组、回归期（本阶段无回归期数据）；同重量最高次数按单组计不累计；自重/计时不套用重量 PR。
- 统计数值（完成率、三桶、PR、记录级判定）一律由 mock 服务端派生，前端只渲染不重算；确认任何草稿后现算更新 `data_updated_at`（用 mock 时钟）。

### 3.4 契约与 mock（含后端交接收口）

- **收口项（低成本、与交接清单相交）**：`ReviseRequest` 增加 `revision`（不匹配按 `draft_modified` 拒绝，交接 F3）；`ConfirmResult` 增加后端提交凭据字段（`committed_revision`、`committed_business_version` 及各 kind 结果 id，交接 F4），既有 `newly_committed/summary` 保留为 mock 填充的展示扩展字段。
- **展示形状扩展**：`TrainingRecord` 增加服务端派生的 `judgement?: Buckets | null`（无对照安排为 null）与对照摘要（原计划组数、当次安排组数、接受时间）；记录列表继续用 `RecordSet` 兼容视图，不迁移 `SetFacts` 直渲。
- **mock 专用新增（已拍 2026-09-12）**：`GET /api/arrangements` 返回已接受安排（`{id, accepted_at, target}`），镜像 `arrangement_revisions` 行；后端 S3-14 未提供该读回端点，接真实后端时补同形端点或等价投影（归联调阶段收口）。
- **mock 统计现算**：`/api/stats` 全量改为现算（含 `per_week`，不再用种子字面值）；确认/重算路径统一走同一统计函数。
- **种子重设**：`default` 种子按 3.5 固定日期与事实重设；移除 `CHECKIN_ENABLED` 门禁，打卡剧本正式开放；受影响的 stage2 探针一并修正，不放宽断言。
- **更懒路径的取舍**：交接 F1/F5–F9（端点拆分与形状映射）**不在本阶段做**——现有聚合端点在 mock 上工作正常，全面镜像后端端点面留到获授权接真实后端的阶段，以 handover 为映射正本，改动收敛在契约与少数渲染分支。

## 4. 明确不做

- 不接真实后端、真实模型或真实 Agent；不修改 `../backend/`、`../pre-prj/` 决策正本。
- 不做记录更正、作废、历史修订 UI 与待补全的补全交互（Stage 4 前端）。
- 不做复盘正文生成、基于统计的渐进/负荷建议、中断接回、动作替代完整流程（Stage 5+）。
- 不做「明显状态差」的最低训练版草稿（需删动作表达，超出已拍两种调整字段，归接回阶段一并拍）；该档仅回建议休息文案，不生成结构化处方。
- 不做交接 F1/F5–F9 的端点拆分与形状重构（留到授权联调阶段）；不把 mock 端点声称为真实后端已交付。
- 不做后台锁定任务、可移动 mock 日期、通用排程、记录编辑器、新依赖或测试框架。
- 不把 mock 统计现算声称为真实统计实现；mock 通过不代表真实链路通过。

## 7. 阶段闭环演示剧本（结项门槛）

前置：Stage 0–2 已结项；`npm run dev`；控制端点重置为 3.5「default」种子（mock 日期 `2026-09-11`，当日腿日应训练、尚无安排）。

2. **提出调整**：「今天状态一般，少练点」→ 安排草稿卡展示完整目标快照、建议减 1 组（或 RIR +1，二选一）与预填原因；Diff 为服务端派生的字段级对比。
3. **状态档位分支**：另输入「今天状态非常差，不太想练」→ 仅回复建议休息文案、不生成任何草稿；「正常」档已在第 1 步覆盖（按原计划回复、无草稿）；红旗分支见第 13 步。
4. **内联纠错与服务端校验**：修改减组数/目标 RIR、必填原因 → revise 后 revision+1、Diff 同步；尝试加组、降 RIR、增删动作、空原因 → 服务端拒绝，正式数据不变。
5. **接受即落盘**：确认 → `accepted_at` 落盘、cv+1、`/profile` 今日显示「已接受安排 · 已调整」；刷新恢复；重复确认幂等；当日已按日期规则锁定但减组仍被接受（日程锁定 ≠ 处方锁定）。
6. **指导优先安排**：再问「今天练什么」→ 按已接受安排（减组后目标）回复，不再按原计划。
7. **打卡反馈**：对话反馈实际训练（含一组「朋友帮忙抬起」、一组未报 RIR、热身「递增至 60kg」摘要）→ 记录草稿：逐组结构化事实（辅助标注、RIR 空、热身原文）、「今天」解析为 2026-09-11、自动携带今日安排关联并展示对照摘要、「无辅助」呈现待确认。
8. **纠错与确认**：修改组事实 → revise；确认 → 记录入列表（valid）、W2 完成率 1/3 → 2/3、三桶按当次安排更新、PR 更新、cv+1；重复确认幂等；失败注入后重做，任一步失败全部回滚。
9. **区分三份**：`/records` 该条显示「原计划 3 组 · 当次安排 2 组 · 实际 2 组」；组级判定按当次安排：符合 / 未符合（次数低于下限）/ 待补全（缺 RIR）各归其位；辅助组标注且不进 PR。
10. **无安排训练**：补录一次无安排哑铃弯举加练 → 新训练身份、不计完成率、不进三桶（单独展示实际表现）、事实明确且无辅助则可进 PR。
11. **同日多练与歧义**：同日再记一次 → 新身份；输入「再补一组」歧义 → 草稿前询问「补充上一练还是新增」，选择补充 → 复用身份不增次数；同一安排多次反馈完成最多计一次。
12. **待补全**：打卡缺每组次数 → 可确认 incomplete →「待补全」徽章、不进 PR 与完成率分子；补全交互不在本阶段（Stage 4）。
13. **安全与公共冲突分支**：经 Stage 1 链路新增命中腿日动作的限制 → 再请求今日指导/使用已接受安排 → 整份阻断并列出冲突；红旗种子 → 仅建议线下专业评估、无安排草稿；推进 context_version → `draft_stale` → 一键重算 → 再确认；丢弃草稿后确认被拒。
14. **恢复与收尾**：待确认/已确认后刷新恢复草稿与正式状态；`npm run build` 零错误，证据归档。
