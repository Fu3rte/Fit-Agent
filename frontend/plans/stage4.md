## 1. 阶段目标

1. 更正入口仍在记录页：`/records` 保持只读，每条记录的「发起更正」只把用户带进对话并预填请求，不直接编辑正式事实（01 1.2、前端存档 B2）。
2. 对话负责**定位训练身份**：以用户明确给出的日期／动作／描述定位既有训练；同日多练或候选不唯一时先询问，不自行选择（05 5.1、5.4）。
3. 定位后生成**更正草稿**：同一 `training_session_id` 的完整修订载荷（该次训练全部动作与组事实，不只是差异），用户所述事实更新、未述字段保持原值不编造；确认前正式数据与业务版本不变。
4. 误录整次训练可经**作废草稿**确认作废；不物理删除历史；当前修订为作废时整次退出统计，**不回退采用旧有效版本**（05 5.3）。作废即该训练身份的终态：当前修订为作废后不再接受任何后续更正／复活修订（2026-09-13 owner 拍 A，05 5.3）。
5. 待补全（incomplete）记录经更正修订补齐必填事实后转 valid，并**自动参与 PR**（无需另行确认「纳入 PR」）（05 5.2、06 6.3）。
6. 更正／作废后追加完整修订并切换当前修订指针：**不新增训练身份**，旧修订保留可追溯，统计按最新有效修订重算（05 5.3、06 6.1–6.3）。
7. 旧复盘不被静默改写：依据变化时标记「依据已变更」，正文保留；统计与更新时间由 mock 服务端现算，前端只渲染不重算（06 6.4、前端存档 B2）。

## 3. 本阶段范围与已确认口径

### 3.1 更正（同一训练身份，完整修订）

- 更正对象是**既有训练身份**：更正不新增训练身份、不增加训练次数（05 5.1、5.3）；同日多练各有身份。
- 草稿载荷是该次训练的**完整修订**（全部动作与组事实），不是差异补丁；用户明确说出的差异更新为拟议事实，未提及的字段保持既有修订的原值，**不默认、不清空、不编造**。
- 不可改写：`training_session_id`（训练身份归属）与安排关联快照（记录绑定的是执行时依据的那份安排）。改归属或改关联等于换目标／换依据，必须丢弃草稿后重新提问、重新生成，不能借内联纠错静默改写（05 5.1、5.2；后端纠错白名单 `validate_record_draft_correction` 已按此实现）。
- 可更正范围是草稿中已明确的事实（本阶段演示与断言覆盖动作与组事实）。日期、反馈等其他事实字段沿用同一不可改写边界与「最新有效修订现算」规则；本阶段不为其单列断言（见 §6）。
- 记录侧 RIR 已拍隐藏（2026-09-12 owner）：更正草稿编辑器与展示不出现用力余量字段与 RIR 缩写，确认不落库（stage3 §3.2 沿用）。
- 确认后追加完整修订、切换当前修订指针、`context_version` 恰好 +1，与草稿提交、领域复查、幂等同事务；重复确认幂等返回原凭据；任一步失败全部回滚；未确认的更正草稿不替换旧正式版本（01 1.4、05 5.3）。
- 更正不带正式记录「计划关联」重指向能力：无对照安排的记录保持无对照，有对照的保持原对照，判定口径不变（06 6.2）。

### 3.2 作废（整次退出统计，不删历史）

- 误录整次训练可经草稿确认作废（05 5.3）：作废草稿只承载「作废哪一次训练身份」，不承载可编辑事实；确认前正式数据与业务版本不变。
- 确认后追加一条作废修订并把当前修订指针切到作废：整次退出统计（完成率分子、三桶、PR 均不再计该次），**不回退采用旧有效版本**；历史记录不被物理删除（05 5.3、06 6.3）。
- 作废与更正共用同一确认事务与版本规则（01 1.4）；重复确认幂等返回原凭据；已丢弃草稿不得提交（01 1.3）。**作废即终态（2026-09-13 owner 拍 A，05 5.3）**：某次训练的当前修订为 `voided` 后，该训练身份不再接受任何后续更正／复活修订（含 incomplete 补全）；mock 与演示在草稿生成与确认两处 fail-closed 拒绝，复用既有 `invalid_request` 语义、不新增错误码（状态码按既有记录确认路径映射，由实施者定型）。此约束只作用于当前修订已作废的身份：不删历史、不改身份、不影响普通 `valid`／`incomplete` 记录的更正。
- 作废后记录仍可在 `/records` 查到并标注「已作废」，旧修订可追溯（05 5.3；`TrainingRecord.status` 注释已预留 `voided`）。

### 3.3 补全（incomplete 经更正转 valid）

- 待补全记录经更正修订补齐必填事实（05 5.2 必填边界：日期、归属、动作、组类型、完成数据）后转 valid；补全不新增身份、不自动提交。
- 转 valid 后自动参与 PR，无需另行确认「纳入 PR」；仍无对照安排时不进三桶、不增加计划完成次数（06 6.1、6.2、6.3）。
- 必填事实仍不完整时可继续以 incomplete 修订保存，不编造缺失事实（05 5.2）。

### 3.4 展示、统计与复盘刷新

- `/records`、`/review` 保持只读，无输入控件、不新增页面或路由（前端存档 B1/B2）；更正仍从对话发起。
- `/records` 每条记录内联展示：当前修订状态（有效／待补全／已作废）、归属徽章（新增／更正）、既有对照摘要与组级三桶徽章、修订说明；旧修订可在卡内只读追溯（修订时间与内容）。**具体渲染形态为实现细节**（内联、不新增详情页）。
- `/review` 数值全部由 mock 服务端现算：更正／作废确认后重新计算完成率、三桶、PR，并更新 `data_updated_at`；前端不重算、不缓存派生数值（经既有 `DATA_QUERY_KEYS` 失效刷新）。
- 复盘正文不被静默改写：依据变化时 `/api/review` 的 `stale` 标记与 `/review` 徽章「依据已变更·可重新生成」体现；正文与 `generated_at` 保持不变，重新生成交互归 Stage 5（存档 B2、06 6.4）。
- 展示用语沿用既有统一口径：「符合目标／未符合／待补全」「暂无」完成率、无 RIR 缩写。

### 3.5 契约、mock 与公共链路

- 契约先行（D1A）：形状唯一来源 `src/lib/contract.ts`。本阶段需要的形状扩展按既定语义整理、沿用既有命名约定，**拼写由实施者定型**（PLAN.md：传输字段不逐项拍板）；契约注释已预留 `voided`。不得为演示新造未拍的业务语义、端点或错误码。
- 复用既有链路，不建第二套：`revise`（所见 revision 不匹配按 409 `draft_modified` 拒绝）、`confirm`（幂等凭据、`context_version` 恰好 +1）、`discard`、`stale` → `recalc`（01 1.6：仅接受仍为 Pending 且已过期的旧草稿，子草稿 `parent_draft_id` 绑定生成读取时的最新 `context_version`；已确认／已丢弃／未过期拒绝 409 `invalid_request`）、失败注入整份回滚、断线／刷新查询恢复（08 8.7）。
- 重算请求体收口（低成本，正本已冻结）：`POST /api/drafts/{draft_id}/recalc` 按 S4-08 正本携带 `{client_request_id}`，mock 用它实现重算幂等。幂等范围按 01 1.6：同一旧草稿已有 **Pending** 子草稿时重复请求返回同一子草稿（不重复生成）；子草稿进入终态后可再生成——该分支本阶段不实现、不演示（见 §6）。
- mock 修订模型收口：训练记录由「每次确认追加新展平行」改为「按训练身份的最新有效修订 + 保留旧修订」；现算统计只取最新有效修订，作废与旧修订不参与完成率分子、三桶、PR；更正／作废草稿在同一条链路内确认；当前修订为作废时该身份即终态，后续更正／复活在草稿生成与确认两处被拒。
- mock 控制面沿用既有种子与 dev 失败注入，仅扩展到更正／作废确认；不新增业务端点。

## 7. 阶段闭环演示剧本（结项门槛）

前置：Stage 0–3 已结项；`npm run dev`；控制端点重置为「default」种子（mock 日期 `2026-09-11`）。

1. **入口与定位**：`/records` 09-07 记录点「发起更正」→ 跳转对话并预填；发送后对话定位到该训练身份（同日多练不猜），回复说明将按同一训练身份生成完整修订草稿。
2. **更正草稿**：草稿卡展示完整修订载荷与 Diff（修改前 → 修改后）、标注「更正（不新增训练身份）」；未述字段保持原值；编辑器无 RIR 字段。
3. **内联纠错与越界拒绝**：修改组事实 → `revise` 后 revision +1、Diff 同步；尝试改训练身份或安排关联 → 服务端拒绝、正式数据与草稿身份不变；用过期 revision 确认 → 409 `draft_modified`。
4. **确认与刷新**：确认 → 追加完整修订、切换当前修订指针、`context_version` +1；`/records` 展示最新修订（更正徽章 + 修订链，旧修订可只读追溯）；`/review` 三桶按最新事实现算（09-07 第 2 组次数 5 → 6 时由 1/1/1 变 2/0/1）、PR 与 `data_updated_at` 现算更新；完成率不变（同一次仍有效且关联同一日程）。
5. **冲突与重算**：确认前经 Stage 1 链路完成一次正式提交推进 `context_version` → 再确认 → 409 `draft_stale` 并指出变更项 → 一键重算 → 子草稿（`parent_draft_id` + 新旧 Diff，绑定读取时最新版本）；子草稿仍为 Pending 时重复重算 → 幂等返回同一子草稿（不产生第二个子草稿）→ 再确认成功；旧草稿未被修改／自动采纳；丢弃草稿后确认被拒（409）。
6. **作废**：对 09-07 发起「整次录错，作废」→ 作废草稿展示待作废身份、事实摘要与影响范围（退出完成率／三桶／PR，历史保留）→ 确认 → W2 完成率 1/3 → 0/3、三桶不再含该次、PR 现算复核不变（该次非 PR 来源，80kg×8 来自 08-31）；`/records` 该条标注「已作废」且旧修订仍可查；重复确认幂等。
7. **补全**：对 09-05 无安排加练（待补全，缺每组次数）发起更正补齐每组次数 → 确认后转 valid、自动参与 PR（新增该动作条目）；仍不进三桶、不增加计划完成次数；身份不变。
8. **复盘与统计不重写**：`/review` 数值由现算结果提供，页脚 `data_updated_at` 已更新；复盘徽章显示「依据已变更·可重新生成」，正文与 `generated_at` 与变更前逐字一致。
9. **空数据与无法定位**：切到空种子 → `/records` 空态、统计「暂无」；对话要求更正 → 无定位对象时明确回复且不生成草稿。
10. **失败与恢复**：dev 注入失败 → 更正／作废确认整份回滚（记录、修订指针与 `context_version` 不变）→ 重做成功；刷新后草稿与正式状态经业务接口查询恢复；`npm run build` 零错误，证据归档。
