# 未核实动作的 Web Search 与目录补充

## 状态

功能预设，尚未实现。当前目录继续作为只读参考；未核实动作保留原名称与核实状态，有重量时保留真实数值与口径，重量为空时隐藏重量与口径。

## 已确认目标

当动作未在目录内核实时，Agent 调用未来的 Web Search 工具查询动作。查询获得可用结果后，根据结果补充动作信息，并补充到动作数据集。查询没有可用结果时，沿用当前未核实动作处理。

检索与数据集写入属于独立能力。此文档仅保留需求，不添加工具、检索服务、写入端点或自动修改已有计划。

## 现有数据边界

- 数据集：`backend/dataset/actions.agent.json`。
- 数据集 Schema：`backend/dataset/actions.agent.schema.json`。
- 目录加载器：`backend/app/application/business/catalog.py`，启动时验证并加载目录。
- 动作包含 ID、中文名称、器械、目标肌群、重量口径及中英文动作步骤等目录字段。
- `equipment` 的 `body weight` 表示普通自重器械分类。动作变式的外加负重或辅助减重需要明确相应重量口径。
- 计划通过 `exercise_id` 引用目录，目录外动作 ID 为 null。
- 看板通过只读器械映射按真实 ID 查询分类，未核实动作保持未核实标签。

## 实施前必须拍板

- 搜索提供方、调用条件、超时与费用限制。
- 可采信来源、动作身份及变式的核实标准；冲突证据的处理规则。
- 结果是否需用户确认才补充目录。
- 写入正式目录所需的字段完整度，中英文步骤的来源及版权要求。
- 新 ID 分配、同名动作去重、同动作变式的身份规则。
- 来源链接、检索时间、核实状态与变更历史的保存位置。
- 原始 JSON 数据集、SQLite 目录表、内存目录的同步与原子写入规则。
- 目录变更后的前端器械缓存失效规则。
- 对既有待确认快照、当前计划及历史版本的影响与引用更新规则。
- 并发写入、权限控制及失败时的数据完整性要求。

## 验收要求

使用真实检索结果验证身份与字段来源。网络内容作为外部数据处理，不能授权工具调用或业务保存。目录补充遵循完整 Schema 校验与本地访问保护，写入成功前保留当前数据完整。无可用检索结果时保持未核实动作语义，不虚构字段或动作身份。
